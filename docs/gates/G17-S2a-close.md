**Дата:** 2026-11-21 · **Слайс:** G17-S2a (первый из четырёх под-слайсов G17-S2, точка P3) · **Вердикт:** PASS

Карточка — [../current/G17-S2-план.md](../current/G17-S2-план.md); ход — [G17-S2a-worklog.md](G17-S2a-worklog.md).

## Что доказано

- **Контракт результата движка (решение Антона №5).** `lunora.engines.Result`: значение по
  правилу (`Rule` = id спеки + semver, `0.x` до подписи практика) с тегом `stability`, либо
  `not_computed` с причиной из ENGINE-SPEC §1.2. Значение и `not_computed` взаимоисключающи на
  уровне конструктора — частичный результат под видом полного не собрать (fail closed).
  Полный `Signal` с голосованием — S4.
- **Движки не тянут оракулы (ADR-001, ENGINE-SOURCES §6).** Статический тест по AST: пакет
  `lunora.engines` не импортирует swisseph, PyJHora, cnlunar, lunar-python, timezonefinder —
  ни на верхнем уровне, ни лениво внутри функций. AGPL в рантайм не попадает.
- **Нумерология на golden-наборах.** 27 кейсов §9.2 (`G-N01…G-N11`, `G-D01…G-D12`,
  `G-S01…G-S03`) + вариант `G-N06` через пробел — все зелёные против движка
  `lunora.engines.numerology`. Эталон — сама спецификация (метод Баллиетт и Александрова;
  внешнего сервиса нет и не нужно — кириллического канона ни у кого нет). Значения расшифрованы
  из §9.2 без пересчёта (evidence `tests/golden/evidence/numerology-rules-9-2.md`, SHA-256
  спеки).
- **Правила движка покрыты юнит-тестами:** примеры нормализации §1.5 (падеж, Е≠Ё, дефис/пробел,
  частицы отчества, латиница и смешанный алфавит — fail closed с позицией), таблица букв §2
  (контрольные точки Ъ=1, Ь=3, Й=2), свёртки §3.1 (33→6, остановка на 11/22), числа даты
  §4.1/§4.2, флаги свободных и мастер-чисел на итоге цепочки §3.4.
- **Property-тесты (seed фиксирован):** сумма гласных + согласных = сумма всех букв для любого
  имени; свёртка `reduce_free` останавливается только на 11 и 22; любая дата 1900–1999 даёт
  девять ячеек и положительное третье рабочее число.

## Решения Антона, зафиксированные в коде

- **№2 — квадрат для дат с 01.01.2000 (`post2000`): fail closed.** `PSYCHOMATRIX` и все ключи
  квадрата — `not_computed: rule_not_formalized`; числа даты (путь, число рождения) считаются
  (§5.2). Значения формулы «+19» из §9.2 сохранены в evidence как справка, в тесты не идут.
- **№5 — минимальный контракт результата** (значение, `rule_id` + версия, `stability`,
  `not_computed`).

## Открыто (не блокирует)

- **Расхождение внутри спеки §9.2 ↔ §4.3 (G-D08).** Таблица §9.2 для 19.10.1982 называет «флаг
  проверки 19», а §4.3 выводит `KARMIC_DEBT_CHECK` из v1 (источник не определён, тема
  чувствительная). Кейс ожидает `not_computed: out_of_v1`. На решение Антона: оставить проверку
  вне v1 (тогда убрать слова «флаг проверки 19» из §9.2) или вернуть её в v1 с источником.
- **G-S04** — профиль стейкхолдера: дата рождения — ПДн, в репозиторий не кладётся; кейс
  `known_gap`, тест идёт только с закрытым fixture (`LUNORA_PRIVATE_NUMEROLOGY_FIXTURE`).
- **Тексты значений** (ячеек, линий, чисел) — переписываются своей формулировкой, не в S2a
  (§10.2, слой содержания).
- **Влияние линий (§5.5) и переходы (§7.2)** считаются и сохраняются, но пользователю в v1 не
  показываются (`skeletons.md` §3.4) — это слой интерфейса, не движка.
