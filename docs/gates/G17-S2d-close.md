# Close-record G17-S2d — ведический движок (Джйотиш)

**Дата:** 2026-11-22 · **Слайс:** G17-S2d (ведический движок; точка P3) · **Вердикт:** PASS
**Критерий:** зелёные `make verify` (755 passed) и `make slice-check` (накопительно
S1 + S2a + S2c + S2b + S2d). Карточка — [../current/G17-S2-план.md](../current/G17-S2-план.md).

С этим слайсом **построены все четыре движка** (нумерология, западный, Ба-Цзы, ведический) и
каждый доказан на golden-наборах против внешнего эталона — содержательный критерий гейта P3.
**Переключение рантайма** (уход pyswisseph/cnlunar/timezonefinder, переписывание `calc.engine`)
вынесено в отдельный под-слайс **G17-S2e** по заранее одобренному решению Антона №4 («раздуётся
— отдельный под-слайс, S2d не пухнет»): оно меняет контракт API, форму хранимого чарта,
слой интерпретации, бота и `test_calc.py` — это интеграция, а не ещё один движок.

## Настройки эталона (Jagannatha Hora 8.0, спайк П-2)

Под них подстроен движок (карты A, B, D): айанамша **True Lahiri / Chitrapaksha**; узлы
**средние**; положения **истинные геометрические** (геоцентрические, без аберрации); даши — true
sidereal solar years, старт от Луны. Место на бланках помечено «Massachusetts, USA»
косметически — читали по координатам (наши).

## Что доказано

- **Раши, лагна, бхавы (§4.1), накшатры и пады (§4.2).** Движок `lunora.engines.vedic` поверх
  `_ephem`: сидерические долготы девяти грах (7 планет + средний Раху/Кету) из **истинных
  геометрических** положений (новая `eph.body_geometric` — без запаздывания света и аберрации) по
  айанамше Лахири (§2.7). Все дискретные значения совпали с JH по всем трём картам: раши,
  накшатра, пада, бхава, лагна, ретроградность.
- **Ключевая калибровка кадра (указание Антона).** При истинных геометрических положениях +
  средних узлах наш сдвиг к JH — **постоянный −55,8″** (разброс по телам ±0,3″, включая узел).
  Это чистая разница айанамши: JH True Chitrapaksha, у нас Лахири №1 (§2.7). Отнесено к
  «настройкам эталона», **не подгонялось**; дискретных значений не меняет. Считай движок по
  видимым положениям (с аберрацией) — добавился бы переменный сдвиг до ~20″ по телу; поэтому
  ведический кадр берёт геометрические положения.
- **Пограничный раши (§4.1).** Карта B Сурья 0 Ge 02′55″ (~3′ от границы Вришабха/Митхуна) —
  обязательный кейс: знак Митхуна совпал с JH, помечен `stability: range`.
- **Вимшоттари-даша (§4.3).** Последовательность МД от накшатры Чандры совпала с JH по A, B, D
  (A: Раху→Гуру→Шани→Будха→…; активная на 16.11.2026 — МД Будха, АД Будха–Шукра). Даты даш —
  `can_vote:false`, продукт до года: наши даты на ~4 суток позже JH (Y=365,25 vs true sidereal
  solar year + доля накшатры при другой айанамше) — класс «длина года»; **год** начала каждой
  МД совпадает с JH.
- **Варги D9/D10 (§4.4).** Навамша — floor(λ_sid/3°20′), сверена с колонкой Nava бланков JH
  (Гуру карты B — варготтама Мина); дашамша по правилу чётного/нечётного знака.
- **Дифф против Swiss Ephemeris (независимый код, группа [oracle]).** `tests/diff/test_vedic_oracle`:
  (1) наш движок ↔ SE под Лахири (TRUEPOS + средний узел) — долготы ≤ 2″, раши/накшатры точно по
  A/B/D; (2) SE под True Chitrapaksha воспроизводит снятые долготы JH ≤ 1″ — подтверждает съём и
  что JH = SE + настройки П-2; (3) сдвиг Лахири→Chitrapaksha постоянен (≈56″). PyJHora не взят —
  капризный API; SE чище и это ровно движок внутри JH.
- **Минимальный контракт (решение №5).** `signals()` → `Result` с `v.rashi`/`v.dasha.vimshottari`
  (даша помечена `range`, `can_vote:false`). Оракулы вне рантайма (ADR-001,
  `test_no_oracle_imports`: `vedic` не импортирует swisseph/jhora).
