## Зачем слайс

Внешнее ревью ядра (принято Антоном) показало: доказанность проверялась на уровне **движка**, но
**продуктовая проекция** `calc/engine.py → FullChart` собиралась вручную и теряла доказанные
величины; точность времени, спорный пояс, пол и ФИО не доходили до карты; непосчитанное роняли
молча. Это механизм F04. P3 понижена до CONDITIONAL; слайс доводит сквозной путь до того, что видит
пользователь, и пересобирает вердикт.

## Что доказано (сквозными тестами через `calculate(BirthData)`/`onboard`)

- **F01 — точность → интервал.** `precision → tolerance_minutes` (±0/30/60/180/сутки) проведён в
  `resolve`; каждая время-зависимая дискретная величина несёт `stability` (`stable`/`range`/
  `undetermined`) с вариантами. Повторённый час (fold) даёт две гипотезы смещения в карте.
  (`test_p3_sweep::test_f01_*`)
- **F02 — место/регион через весь путь.** `place_id`/`region` ведут от API через `BirthData` и
  `resolve` в хранимую модель; Джизак (TZD-001) и Тирасполь/Бендеры (TZD-002) через `onboard` дают
  две гипотезы UTC и `dispute_id` в `calculation_runs`. Места добавлены в мин. справочник.
  (`test_onboard_p3::test_f02_*`)
- **F03 — ли-чунь/цзе на суточном интервале.** При неизвестном часе столп года проверяется на всём
  интервале суток → `range` [癸亥, 甲子] (было `stable` по опорной точке). (`test_f03_*`)
- **F04 — v1-контракт карты (корневая задача).** Продукт приведён к data-model v3 и собирается из
  `engines.*.signals()`: веда — лагна + D9/D10 + активные МД/АД; запад — ASC/MC + дома по цельным
  знакам (`house_whole`) + Плацидус; Ба-Цзы — да-юнь (пол обязателен); нумерология — **оба контура**
  (дата + имя, дельта изменения имени). Каждая не-v1 величина — явный `not_computed`.
  (`test_product_contract`, `test_p3_sweep::test_f04_*`)
- **F05 — границы по угловой скорости.** Поиск смен асцендента/лагны — шагом по непрерывной угловой
  скорости, не сеткой; property-тест 66°: совпадает с плотной сеткой 1 с, сетка 10 мин теряет смены.
  (`test_stability::test_f05_*`)
- **F06/F07 — LLM-защита и провенанс.** В LLM-пакет `range → «A или B»`, `undetermined`/непосчитанное

  `test_f07_*`, `test_pii_*`)
- **F08 — происхождение карты E.** GB-03 исправлен: день-граница — **rule-derived (§5.4) + cnlunar**,
  не ручная сверка bazi.biz с TST. Поправлены golden и close-record S2b.
- **F09 — запрет `computed(None)`.** `Result.computed(None)` падает; MATURITY/HEART/PERSONA без
  значения и латиница/смешанный алфавит ФИО — явный `not_computed`. (`test_f09_*`, контракт)
- **F10 — `element_balance → visible_stem_counts`** (счёт только видимых стволов; полный баланс §5.7

- **F11 — ведический `stability`.** `near_boundary` («близко к границе» при точном времени) отделён

- **Анти-F04 сторож покрытия.** `test_product_contract`: каждый `technique_id` из `engines.*.signals()`

- **152-ФЗ.** Пол и ФИО входят в движки и хранимую карту, но тест-сторож падает, если они (или
  дата/место/координаты) попадут в LLM-пакет или провенанс.

## Вход и решения Антона

- `BirthData` несёт структурное ФИО (`FullName`), `sex`, `name_current`, `place_id`, `region`.
- Решения Антона (F04): нумерология — два контура (имя+дата) — **канон** (NUMEROLOGY-RULES стр. 17),
  здесь только интеграция ФИО в контур имени; пол обязателен, да-юнь проведена. Приватность: имя/пол
  не в LLM и не в аналитику.
- В-1 (вынесен координатору, решал по рекомендации): ФИО латиницей/смешанным алфавитом на онбординге
  → `onboard` отвечает **422** (карта не сохраняется), движок вне API — `not_computed:
  name_not_supported`. Новые причины `not_computed` добавлены в ENGINE-SPEC §1.2.

## Вердикт точки P3 (пересборка)

**P3 — ЗАКРЫТА (пересобрано).** Корректность ядра доказана не только на движках (S2a–S2e), но и
**сквозь продуктовую проекцию** `calculate(BirthData)`/`onboard`: все доказанные v1-величины четырёх
школ доходят до хранимой карты, непосчитанное — явный `not_computed`, точность/пояс/пол/ФИО проведены,
провенанс полон, ПДн не утекают в LLM. Структурный сторож покрытия запрещает повторение F04. Гейт G17
по корректности ядра — закрыт на уровне сквозного продукта.
