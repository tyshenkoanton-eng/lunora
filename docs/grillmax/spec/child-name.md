# Имя ребёнка: подбор и проверка — спека блока

**Статус:** ✅ глубокая. Обе услуги приведены к единому методу.
Соответствует прототипу (`wireframes/02-report.html`, бейдж от v698).

**Что это:** две нумерологические услуги в витрине «Ребёнок» (`shopChild`,
Р-18). Отличаются тем, кто приносит имена:

| Услуга | Ключ | Цена | Кто приносит имена |
|---|---|---|---|
| Подбор имени | `childName` | 990 ₽ | мы предлагаем список под отчество и фамилию |
| Проверка имён | `childCheck` | 490 ₽ | у вас уже есть список, мы его оцениваем |

Пересечение убрано осознанно: «Подбор» больше не обещает проверять ваши
варианты (это отдельная «Проверка»).

## Метод (общий для обеих услуг)

Считает одна школа — **нумерология**, таблица Пифагора для русского
алфавита (в прототипе `CYR_NUM`: каждой букве число 1–9; Ь и Ъ не считаются;
11 и 22 не сокращаются).

- **Три числа имени** (по полному ФИО: имя + отчество + фамилия):
  - **Умеет** — по всем буквам,
  - **Хочет** — по гласным,
  - **Кажется** — по согласным.
- **Число по дате рождения — Основа.**
- **Сравнение с датой** — число имени **Умеет** против **Основы**, вердикт
  словами: **совпадает / дополняет / спорит** (как в совместимости, без
  процентов). Если даты нет — одна строка «дата не указана», считаем только
  по имени.

**Зафиксированные решения:**
1. Сравнение с датой: Умеет ↔ Основа, словами.
2. Правило «особых» чисел **13/14/16/19 не применяется** (слишком
   фаталистично для детского продукта).
3. Три числа называем **Умеет / Хочет / Кажется**, число по дате — Основа.
   Слово «судьбы» не используем.

Разные написания дают разные числа (София и Софья: по всем буквам 3 и 11),
поэтому написание фиксируется явно.

## Подбор имени (`childName`)

### Витрина (Р-09-10)

- **Лид:** «Составим список имён для ребёнка и посчитаем, как каждое
  сочетается с отчеством и фамилией. Расчёт по нумерологии.»
- **«Что вы узнаете»:** Список имён (до 8, со значением и происхождением) ·
  Почему подошло каждое (три числа и сравнение с датой) · Как имя выглядит
  целиком (запись в документах).
- **«Что понадобится»** (`needItems`): Пол ребёнка · Отчество · Фамилия ·
  Дата рождения. Заметка (`needNote`): если ребёнок ещё не родился, дату
  можно не указывать, тогда считаем только по имени.
- **Превью** страницами (`preview:'doc'`, `docPages`): «Посмотреть пример
  документа».

### Форма (Р-10-10, Р-10-10-2)

Многошаговая, как разбор ребёнка: степпер на всю ширину (`stepper` по числу
шагов). Состояние в `CN`, шаг в `CN_STEP`, сброс в `prodPage`, шаг из
каталога через `cnstep`.

- **Шаг 1 «Данные ребёнка»:** Отчество (необязательное), Фамилия, Пол
  (сегмент Девочка/Мальчик, предвыбран). **«Дальше» активна при
  заполненной фамилии** (пол задан по умолчанию, отдельного гейта не
  требует).
- **Шаг 2 «Дата рождения»:** день/месяц/год; заметка «если ещё не
  родился…». Дата необязательна.

Имена пользователя форма **не собирает** (подбор — это наши предложения).

### Проверка (Р-11-10)

Блок данных: «Разбор» с типом, линия, затем поля с подписями (Пол,
Отчество, Фамилия, Дата рождения; дата без значения показывается как «не
указана»).

### Результат (Р-14-10)

Заголовок «Подбор имени ребёнку». Порядок: данные ребёнка (поля с
подписями) → «Коротко» (с выводом, какое имя ложится ровнее) → структура
документа.

**Структура документа** (по образцу конкурентов):
1. Шапка: отчество, фамилия, пол, дата.
2. Коротко: правило, по которому имя «сильнее» (Умеет совпадает с Основой
   или дополняет), и вывод.
3. Таблица всех имён: Имя · Умеет · Хочет · Кажется · С датой (словами).
4. «Что предлагаем мы» (до 8 карточек): числа, сравнение с датой, что даёт
   и на что обратить внимание (нейтрально, без приговоров).
5. Как выбрать между ними (прочитать полное имя вслух и т.п.).
6. Значение и происхождение.
7. Вопросы и ответы (три коротких).
8. Как посчитано: суммы по буквам для каждого имени и число Основы, чтобы
   можно было проверить.

Пример Софьи построен на отчестве Дмитриевна, фамилии Тыщенко, дате
9 мая 2019 (Основа 8). Числа посчитаны движком (`CYR_NUM`), не выдуманы.

## Проверка имён (`childCheck`)

Та же логика, что в «Подборе», но имена приносите вы, а не мы.

### Витрина (Р-09-11)

Построена по образцу «Подбора».

- **Лид:** «У вас уже есть имена для ребёнка. Посчитаем каждое по
  нумерологии и покажем, как оно сочетается с отчеством, фамилией и датой
  рождения.»
- **«Что вы узнаете»:** каждое имя по числам (Умеет/Хочет/Кажется) ·
  сравнение с датой словами · сравнительная таблица · честные ограничения.
- **«Что понадобится»** (`needItems`): имена, которые проверяете · отчество ·
  фамилия · дата рождения; заметка про нерождённого ребёнка.
- **Превью** страницами (`preview:'doc'`, `docPages`).

### Форма (Р-10-11, Р-10-11-2)

Многошаговая, как в подборе: степпер на всю ширину. Состояние в `CC`,
шаг в `CC_STEP`, сброс `ccReset()` в `prodPage`, шаг из каталога через
`ccstep`.

- **Шаг 1 «Имена для проверки»:** список строк имён (по одной пустой при
  открытии, плейсхолдеры «Введите первое имя…»). Кнопка «+ добавить имя»
  добавляет строку, до 5; на строках крестик `✕` удаляет (минимум одна
  строка остаётся). Ниже Отчество (необязательное) и Фамилия. **«Дальше»
  активна, когда заполнено хотя бы одно имя и фамилия** (это анкер, с
  которым имя сочетают; витрина обещает сверку с фамилией). Имена в
  состоянии — массив `CC.names`.
- **Шаг 2 «Дата рождения»:** день/месяц/год; заметка «если ещё не
  родился…». Дата необязательна.

### Результат (Р-14-11)

Заголовок «Проверка имён». Структура как у подбора, но по вашим именам:
шапка (отчество, фамилия, дата) → «Коротко» с выводом → таблица ваших имён
(Умеет/Хочет/Кажется + С датой) → разбор каждого имени → как выбрать →
вопросы и ответы → как посчитано с суммами по буквам. Числа сверены с
движком (`CYR_NUM`).

**Чем проверка отличается от подбора** (по разбору конкурентов: один отчёт
на оба случая, спокойный тон без страшилок):

1. **Показываем всё, включая «спорит».** В подборе спорящие имена убираем,
   в проверке скрывать нельзя: человек пришёл узнать про конкретное имя.
2. **Тон «спорит» мягкий.** Короткое объяснение по числам и спокойный
   вывод (имя можно оставить). Без «исправьте имя».
3. **Поправка только через законную форму записи** (София/Софья дают 3 и
   11; Алёна/Алена тоже разные). Советовать «добавьте букву» нельзя.
4. **Близкие замены** (1–2) для спорящего имени — follow-up, пока не
   отрисовано.
5. **Незнакомое имя:** числа считаем всегда; значения нет — пишем «в нашей
   базе значения нет». Когда добавляем значение/происхождение — один
   источник и пометка «по одной из версий».

**Вердикт «С датой» (черновое правило, сверить с нумерологом).** Сравнивает
Умеет с Основой:
- **совпадает** — Умеет равно Основе;
- **спорит** — встречаются число устойчивости (4 или 8) и число движения
  (3 или 5);
- **дополняет** — остальное; среди дополняющих «ровнее» те, чьё Умеет ближе
  к Основе.

Правило показано в блоке «Как это посчитано», чтобы вердикт был
воспроизводим, а не подобран вручную.

**Правило 13/14/16/19 не применяем** (решение по всему детскому блоку,
слишком фаталистично). Но промежуточные суммы в «Как посчитано» показываем
честно: `88 → 16 → 7`, а не `88 → 7`.

## Крайние случаи

- **Нет даты** (ещё не родился): считаем только по имени, столбец «С датой»
  заполняется строкой об отсутствии даты.
- **Нет отчества**: считаем по тому, что есть; минимум — имя и фамилия.
- **Е/Ё и написание**: София/Софья считаются по-разному, написание
  фиксируется; при сомнении можно посчитать оба.

## Правила и расчёт

- Таблица букв, гласные, правило 11/22, Ь/Ъ — `CYR_NUM`/`VOWELS_RU`/
  `numReduce` прототипа; `dict-numerology.md`.
- Сравнение с датой словами — та же шкала, что в совместимости
  (`compatibility.md`): совпадает / дополняет / спорит.

## Решения, принятые при реализации

1. **Две раздельные услуги** по тому, кто приносит имена; пересечение
   («проверим ваши варианты») из «Подбора» убрано.
2. **Форма подбора — многошаговая** со степпером на всю ширину, как разбор
   ребёнка. **Форма проверки** тоже многошаговая, со списком своих имён
   (добавление/удаление, до 5).
   Решение подтверждено после разбора конкурентов: держим две услуги, а не
   объединяем проверку в подбор отдельным полем «свои варианты».
3. **Проверка данных — единый формат** «заголовок + линия + поля с
   подписями» (как на всех экранах проверки).
4. **Документ подбора перестроен** вокруг таблицы имя → числа → дата; числа
   сверены с движком; «судьбы» и приговоры убраны; правило 13/14/16/19 не
   применяется.

## Открытые вопросы

1. **Методику сверить с нумерологом** перед релизом: какое имя считать
   «сильнее», трактовки чисел, правило Е/Ё.
2. **Уменьшительные формы** (Оля/Оленька дают свои числа) — добавить
   отдельным необязательным блоком (сейчас только упомянуты).
3. **Таблица пар Основа × Умеет** для вердикта «С датой» — сейчас черновая
   (см. выше), нужна проверенная у нумеролога.
4. **Список законных пар написаний** (София/Софья, Алёна/Алена и т.п.) для
   поправки через форму записи.
5. **Близкие замены** для спорящего имени (1–2 по звучанию/смыслу, но ровнее
   по числам) — логика не отрисована.
6. **Необязательные добавки** (сочетание с числами родителей, проверка
   инициалов) — решить, нужны ли. Пока не делаем: числа родителей ближе к
   совместимости, инициалы — отдельная мелкая проверка.
