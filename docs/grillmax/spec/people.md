## Л-13 · С кем легко и с кем трудно (`peopleRel`)

**Назначение.** Тема отношений плюс то, что можно сказать о людях вокруг **без их данных** — по знакам, с честной границей к платному разбору.

**Состав (текущий прототип).**
- Назад → `shopPeople` (раздел «Про людей»); крошка «Про людей».
- Заголовок «С кем вам легко, а с кем трудно».
- **«Что мы знаем без данных»** — body-text тремя абзацами: **С кем вам легко** (Рыбы, Скорпион, Рак — «выдерживают вашу глубину»), **Кто вас учит** (Козерог — «тяжело и полезно одновременно»), **С кем осторожно** (Близнецы — «не плохо, а говорите на разной скорости»).
- **Оговорка** (`orient`): «Это **по знакам** — то есть про двенадцатую часть человечества. По настоящей карте конкретного человека получается совсем другое.»
- **«Что можно посчитать точно»** — карточки: «Разобрать конкретного человека» (`data-prod=compat`, **990 ₽**) · «Смена фамилии» (заглушка, 490 ₽).

| Элемент | Поведение |
|---|---|
| «Разобрать конкретного человека» | → конвейер `prod=compat` (совместимость). |
| «Смена фамилии» | Заглушка (`stub`) — не кликается в прототипе. |

⚠️ **Прямо сказано, что это по знакам** — то есть про двенадцатую часть человечества. По настоящей карте конкретного человека получается другое, и за этим — в платный разбор. Это граница бесплатного и платного, подаётся честно, тем же приёмом, что «школы по знаку» в бесплатных темах.

**Вход:** из раздела «Про людей» (`shopPeople`) и из профиля (тема отношений).

## Л-14 · Добавление человека (`addPerson`) — два состояния

**Назначение.** Добавить близкого, чтобы видеть его день в «Сегодня» и строить совместимость. Это единственный экран добавления: отдельного экрана-питча (прежний С-03) нет, его ценностная вводка живёт в начале этой формы. Открывается **прямо** из «Сегодня» (плашка/слот), минуя промежуточный экран.

**Два состояния через флаг «первый / следующий»** (отдельные адреса Л-14-1 / Л-14-2):
- **Л-14-1 · первый (бесплатно)** — кнопка «Добавить человека» → `today`; футер «Первый человек — бесплатно». Вход: пустая лента (С-01-2).
- **Л-14-2 · следующий (платно)** — цена в заголовке («Добавление человека · 290 ₽»), кнопка «Добавить человека · 290 ₽» → оплата (`payConfirm` · `paykind=slot` → payGate → payOk → `today`); футер «Это разовый платёж». Вход: лента с людьми (С-01-1). 🔑 Форма идёт **до** оплаты, но про платность не застаёт врасплох: цена показана на входе — и на плашке «Добавить ещё человека · 290 ₽» на «Сегодня», и в заголовке самой формы.

**Состав — форма (текущий прототип).**
- Назад → `today`; заголовок «Добавление человека» (+ «· 290 ₽» в платном).
- Шапка-ценность (то, что раньше было отдельным питчем): «Его прогноз будет рядом с вашим каждый день. Вы увидите, в чём совпадаете, где расходитесь и что с этим делать именно вам.»
- Интро (даёт контекст и при холодном заходе, не только из «Сегодня»): «Раздел Сегодня это ваш ежедневный прогноз по вашей карте: какой складывается день и что с ним делать. Сюда же можно добавить близкого человека.» → затем ценность: «Его прогноз будет рядом с вашим каждый день. Вы увидите, в чём совпадаете, где расходитесь и что с этим делать именно вам.» → «Чтобы добавить человека в ленту, укажите его данные.»
- Строка «Чтобы добавить человека в ленту, укажите его данные» — **выделена как подзаголовок** (крупнее и жирнее), **над ней линия-разделитель**: отделяет вводный контекст от самой формы.
- Поля — **как в онбординге владельца**, тремя разнесёнными блоками (не впритык): (1) **Полное имя** · **Отчество** · **Фамилия** сгруппированы вместе, под ними подсказка «Фамилию и отчество можно не заполнять. Но с ними нумерология расскажет о нём подробнее»; (2) **Пол** — сегмент **Мужской / Женский**, Мужской первый и по умолчанию (чаще добавляют партнёра); (3) **Дата рождения** в формате день/месяц/год. Между группами и до блока кнопки — увеличенные отступы. В прототипе поля показаны **пустыми** (чтобы виден был незаполненный вид формы): ФИО заполняются тапом, дата — через шторку-пикер по тапу на поле. **Время рождения не спрашиваем** (дневному слоту не нужно), **«кем приходится» убрано** (не вход в расчёт).
- **Согласие + кнопка — в одном блоке с фоном** (`.docfoot boxed`): короткая галочка «Подтверждаю, что имею право передать данные этого человека» с инфо-значком «i» в конце (тап → нижняя шторка «Зачем это согласие» с мягким объяснением про обработку чужих ПД; тап по «i» не ставит галочку) + кнопка под ней. Кнопка (первый «Добавить человека бесплатно»; следующий «Добавить человека · 290 ₽» + строка «Это разовый платёж») **неактивна (`off`), пока согласие не отмечено** — гейт. Пол в форме переключается (Мужской/Женский). Прежние футеры («первый бесплатно», «данные можно удалить») убраны: «бесплатно» теперь на кнопке, удаление данных живёт в карточке человека (Н-08).

🔑 **Гейт кнопки — обязательные поля + согласие.** Кнопка «Добавить человека» активна, только когда заполнено **имя**, выбрана **дата рождения** (все три поля день/месяц/год) и отмечено **согласие** (три условия вместе). Фамилия, отчество и пол необязательны. В прототипе: имя/отчество/фамилия заполняются **тапом по полю** (подставляется пример), дата рождения — **тапом по каждому полю открывается нижняя шторка-пикер** (переиспользуется `pickSheet` онбординга со списками день/месяц/год, но пишет в поля формы, не в данные владельца), согласие — галочкой; любое из обязательных незаполненных держит кнопку неактивной.

🔑 **Согласие обязательно по закону, не для перестраховки.** Пользователь вводит **чужие** персональные данные (имя, дата рождения другого человека). По 152-ФЗ для их обработки нужно правовое основание; стандартный механизм — пользователь-инициатор подтверждает, что имеет право передать эти данные. Поэтому галочка остаётся и **гейтит** кнопку. Для **своих** данных согласие берётся на онбординге (О-05). Финальную формулировку согласовать с юристом.

🔑 **Решение (Антон): форма без времени, но с полным именем.** Дневной движок считается **от даты + имени** (без минуты рождения): дата даёт нумерологию (личный день), Ба-Цзы день-мастера и западные планеты с медленными транзитами; полное имя (имя/отчество/фамилия) даёт контур имени в нумерологии. Поэтому форма повторяет онбординг владельца, но **без времени и без места**: они входы **платных** продуктов (совместимость, полный разбор, дома/восходящий, ведическая) и спрашиваются на экране данных конкретного продукта (`prodData` Р-10), а не авансом. «Кем приходится» убрано — это не вход в расчёт. Полоса глубины «Что получится посчитать» убрана: она мерила глубину платных разборов, а для дневного слота даты достаточно.

⚠️ **Времени рождения второго человека почти никогда нет** — это массовый случай. Поэтому дневной движок на нём и не завязан: без времени он теряет только дома, восходящий и ведическую (их держим для владельца и платных разборов), а нумерология + Ба-Цзы день-мастер + западные планеты работают от даты.

**Данные.** Пишет карточку человека (`PEOPLE`); требует согласия на передачу чужих ПД (`data-model.md`). Обещание бесплатного пересчёта при уточнении — то же правило идемпотентности, что и для своей карты.

## Л-15 · Совместимость (`compat`)

**Назначение.** Выбор типа связи перед платным разбором пары.

**Состав (текущий прототип).**
- Назад → `shopPeople`; крошка «Разборы · про людей».
- Заголовок «Совместимость»; лид «Считается одинаково, а читается по-разному. От типа связи зависит, какие показатели смотреть первыми.»
- Четыре карточки типа связи, **все** ведут в конвейер `prod=compat`: **Любовь и отношения** · **Дружба** · **Деловое партнёрство** · **Родня**. У каждой — своя подпись, что читается первым.

🔑 **Расчёт один, чтение разное.** Тип связи не меняет вычисление карт пары — он задаёт, какие показатели выводятся первыми. Это прямо сказано в лиде, чтобы человек не думал, что «дружба» и «любовь» — два разных платных продукта.

**Данные.** Строится по картам двух людей. Второй человек при неполных данных (обычно без времени) — глубина ниже, подаётся честно (см. `depth-model.md`). Гуна-милан (ведическая) считается; подача 24/36 — открытый вопрос продукта.

## 🔑 Решение: что считается добавленному человеку (compute vs. разбор)

**Проблема.** Бесплатный человек получает слот в «Сегодня», где его день подаётся «через его карту». Легко подумать, что для этого нужно посчитать его **полный разбор по четырём школам** и фактически отдать платный продукт. Это не так — важно развести **расчёт карты** и **генерацию разбора**.

**Решение (Антон).**
- Добавленному человеку считается **карта в объёме, который нужен дневному движку** (позиции/числа), а **не** полный натальный разбор по школам.
- **Дневной слот** использует только дневные сигналы: сейчас — **нумерология** (личный день, от даты, время не нужно); позже — **столп дня Ба-Цзы** (дёшево, от даты) и **транзиты** (нужны натальные позиции: дата + город, **без времени** — берутся медленные аспекты). Тот же дневной движок, что и для «Ваш день» пользователя.
- **Платными остаются** полный разбор человека и **совместимость** (синастрия по двум картам + генерация текстов движком к G10). Расчёт позиций ≠ выдача совместимости.
- **Экономика.** Бесплатный слот — крючок: увидел его день → захотел глубже → покупает совместимость или третий слот. Стоимость обслуживания ограничена дневным расчётом.

**Для реализации.**
- Не закладывать генерацию полного разбора на каждого добавленного человека — только расчёт, нужный дневному слоту.
- Считать **лениво** (при добавлении / первом показе) и **кэшировать** день, а не пересчитывать с нуля каждое утро.
- Набор школ-сигналов бесплатного дневного слота — **продуктовый параметр** (минимум нумерология + столп дня; транзиты — по решению о нагрузке). Зафиксировать вместе с движком дня (`today.md`, `engine-spec.md`).
- Время рождения второго человека обычно отсутствует — дневной слот на нумерологии его и не требует (см. `depth-model.md`).

## Н-08 · Карточка человека (`delPerson`) → Н-20 · Удаление (`delPersonConfirm`)

Удаление человека — **два шага**, симметрично удалению своих данных (Личные данные Л-16 → Н-09):

**Н-08 · карточка человека (`buildDelPerson`).**
- Назад → `myPeople` (раздел «Добавленные люди»).
- ФИО человека · строки данных (дата рождения, город).
- **Связанные документы** — карточки разборов, построенных на этом человеке (если есть).
- **Лента** — статус-карточка «Прогноз рядом с вашим» (в ленте / не в ленте) и действие по состоянию (см. ниже «Лента: вкл/выкл и экономика слотов»).
- Внизу — красная кнопка **«Удалить данные»** → `delPersonConfirm`. Это удаление **данных целиком**, отдельно от «Убрать из ленты».

### Лента: вкл/выкл и экономика слотов (Н-08)

🔑 **Платим за слот в ленте, человека в слоте меняем свободно.** 290 ₽ — это цена **места** в ленте, не конкретного человека. Модель «лояльная»: добавил, передумал, поставил другого — без новых платежей.

- **Человек в ленте** → кнопка-призрак **«Убрать из ленты»** (бесплатно). Его день перестаёт стоять рядом с вашим; данные и купленные разборы сохраняются, **слот остаётся за вами** — в него можно поставить другого.
- **Человек не в ленте, есть свободный слот** → кнопка **«Добавить в ленту»** (бесплатно). Занимает свободное место.
- **Человек не в ленте, свободных слотов нет** → кнопка **«Добавить в ленту · 290 ₽»** → оплата (payConfirm · slot → payGate → payOk). Покупка **открывает ещё одно место** (не привязана к человеку); после оплаты человек встаёт в него. payOk → «Готово» → назад в карточку (уже «в ленте»).
- Первый слот бесплатный (прототип: по умолчанию его занимает Дмитрий). Список «Добавленные люди» (Н-07) помечает тех, кто в ленте, подписью «В ленте».

Копирайт склоняется по полу человека (`PRON`): «Ольга добавлена», «её прогноз» — чтобы названный человек не звучал в мужском роде по умолчанию.

**Н-20 · подтверждение (`buildDelPersonConfirm`) — экран как Н-09-1.**
- Назад → `delPerson`.
- **Предупреждение** (`warnbox` без треугольника): вместе с данными этого человека удалятся все связанные документы; если есть документы — их можно сохранить одним архивом перед удалением.
- Сводка данных человека (дата/город), затем связанные документы — карточками.
- Если есть документы — кнопка-призрак **«Сохранить документы»** (`data-save=person`).
- Кнопка **«Удалить данные»** (`data-del=person`, danger) → шторка-подтверждение (простой confirm) → откат через `undo`.

🔑 **Удаление — всегда отдельный шаг-подтверждение.** Экран с данными не удаляет сам; красная кнопка ведёт на экран подтверждения (Н-20), где предупреждение и сохранение документов. То же для своих данных (Л-16 → Н-09).

🔑 **Удаление человека освобождает слот, а не схлопывает его** — чтобы освободившееся место в «Сегодня» было видно как приглашение добавить кого-то ещё, а не исчезало молча.

**Вход:** из раздела «Добавленные люди» (Н-07 `myPeople`, Настройки → Данные → Добавленные люди) — тап по карточке человека. После удаления — откат через `undo` (строка «Восстановить» с обратным отсчётом, возврат на список `myPeople`), что честнее word-confirm для откатываемого действия.
