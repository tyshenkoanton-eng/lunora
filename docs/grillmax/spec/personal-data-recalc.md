# Блок: Личные данные → пересчёт

**Статус:** ✅ согласован · **Экраны:** Л-16-1, Л-16-2, Л-17, Л-23, Л-18
**Связанные доки:** `recalc-flow.md` (флоу), `depth-model.md` (глубина), `idempotency.md` (бесплатный пересчёт и версии документов).

Человек открывает свои данные о рождении, дополняет или уточняет их, и Лунора бесплатно пересобирает карту и все купленные разборы. Процесс устроен так, чтобы правка была видимой (что меняется и на сколько вырастет глубина), а пересчёт — **сразу по подтверждению**: правка данных всегда ведёт к пересчёту, поэтому отдельной опции «позже» и «устаревших» разборов нет (та же логика, что при правке данных человека — `people.md`).

---

## Флоу

```
Профиль → Настройки → Личные данные (Л-16-1)
        [или] Нумерология · контур имени → «Дополнить имя» → Л-16-1

Л-16-1  правка полей инлайн → «Готово» → появляется «Сохранить»
   │
   ▼ «Сохранить»
Л-17  Сохранить изменения?  (подтверждение + предупреждение о пересчёте)
   │   сводка данных + таблица изменений + новая глубина + что пересчитается
   ├─ «Отмена» → назад на Л-16-1 (правки в CHANGES сохраняются)
   ▼ «Сохранить и пересчитать»
Л-23  Пересчёт · анимация (сам, по завершении)
   ▼
Л-18  Пересчитали — что стало другим + список обновлённых документов
   ▼ «Перейти к разборам»
Р-01-2  Разборы · мои разборы
```

Когда все данные уже внесены (глубина 100%), Л-16-1 заменяется вариантом Л-16-2 — дополнять нечего, флоу пересчёта не нужен.

---

## Состояние процесса

Это поля модели на время сессии правки (в прототипе — глобальные переменные, имена даны для привязки).

| Поле | Тип | Смысл |
|---|---|---|
| `DATAFULL` | bool | все данные внесены → показывать Л-16-2, глубина 100% |
| `CHANGES` | map «поле → {from, to}» | накопленные правки за заход; из них собирается Л-17 |
| `TPREC` | enum `t/p/r/n` | выбранная точность времени в пикере (точно / ±30 мин / ±3 часа / не знаю) |
| `RECALC_SEEN` | set | какие документы на Л-18 уже открыли (гасит точку «непрочитано») |

`CHANGES` очищается после успешного пересчёта (дошли до Л-18). `RECALC_SEEN` обнуляется в начале новой анимации пересчёта. Отдельного флага «пересчёт отложен» больше нет: пересчёт всегда идёт сразу по подтверждению.

---

## Глубина расчёта

Правила весов — в `depth-model.md`. Для этого блока важно:

- У каждого недостающего поля свой вклад: **отчество +5%**, **адрес +3%**, **время** — зависит от точности: **точное +30%**, **± 30 мин +20%**, **± 3 часа +14%**, «не знаю» +0%.
- База (текущая глубина до правок) и список недостающего считаются из того, что уже внесено. В прототипе сейчас выставлен **тестовый пресет**: отчество есть, время не указано, адрес нет → база **67%** (см. `depth-model.md`, строка «Дефолт прототипа»). В проде база вычисляется из реальных данных.
- Л-17 показывает `база% → база+вклад%`. Пересчёт всегда бесплатный.

## Экраны

### Л-16-1 · Личные данные (данные неполные)
Ключ `persData`, состояние `s={full:0}`. Группа «Данные и настройки».

**Назначение.** Показать данные о рождении, дать дополнить недостающее, запустить пересчёт.

**Элементы и поведение.**

| Элемент | Поведение |
|---|---|
| Баннер глубины | Текущая глубина + список недостающих полей с «+N%». Закрывается крестиком (косметика). |
| Строки данных | Полное имя, отчество, фамилия, дата, время, город, адрес. Заполненные — текстом; недостающие/неточные — ссылкой-редактором. |
| Ссылка «Указать отчество» | Раскрывает инлайн-поле ввода → «Готово» подтверждает. |
| Ссылка «Указать время рождения» | Раскрывает пикер времени **с выбором точности** (как в онбординге О-04): сегмент-таб `Точно / ± 30 мин / ± 3 часа / Не знаю`, затем час и минуты. «Не знаю» прячет поля времени. |
| Ссылка «Указать точный адрес» | Раскрывает поле адреса с подсказками геокодера (в прототипе — имитация). |
| «Готово» в поле | Записывает правку в `CHANGES` (пара было→стало), обновляет строку, **впервые показывает панель «Сохранить»**. Для времени значение приводится к `чч:мм · <точность>`. |
| «Сохранить» | Ведёт сразу на экран подтверждения Л-17 (без промежуточной шторки). |
| «Отменить» | Сбрасывает `CHANGES`, перерисовывает экран. |

**Переходы.** Вход: Настройки → «Личные данные»; Нумерология (контур имени, путь F2) → «Дополнить имя». Выход: Л-17 (по «Сохранить»).

**Данные.** Читает профиль (имя, дата, место, точность времени). Пишет в `CHANGES` (локально до сохранения).

**Крайние случаи.** Панель сохранения не появляется, пока нет ни одной подтверждённой правки. Повторный вход в «Личные данные» ничего не поднимает: раз пересчёт всегда идёт сразу по подтверждению, «висящего» отложенного пересчёта не бывает.

### Л-16-2 · Личные данные (данные полные)
Ключ `persData`, `s={full:1}`.

Тот же экран, когда глубина 100%: баннер говорит «Глубина расчёта 100%. Все данные внесены», строки отчества/времени/адреса показаны значениями, редакторов и панели сохранения нет. Отдельного экрана-состояния «всё внесено» не делаем — это вариант Л-16.

### Л-17 · Сохранить изменения?
Ключ `confirmRecalc`. Группа «Данные и настройки».

**Назначение.** Подтверждение сохранения: предупреждаем, что связанные разборы будут пересчитаны, и показываем, что именно изменилось. Это единственный шаг подтверждения (промежуточной шторки «позже» больше нет).

**Состав.**
- Подзаголовок «Связанные разборы будут пересчитаны по новым данным».
- Сводка данных: полное имя, дата рождения (с временем), место.
- Таблица **«Изменения»** (фикс-сетка 3 колонки: Что / Было / Стало, вертикальные разделители, перенос по словам; длинный адрес переносится, не обрезается).
- Новая глубина: `база% → итог%` (вклад времени зависит от выбранной точности).
- «Что пересчитается» — список затронутых школ (правило ниже).

| Элемент | Поведение |
|---|---|
| «Сохранить и пересчитать» | Идём на Л-23 (анимация). |
| «Отмена» | Возврат на Л-16-1 (правки в `CHANGES` сохраняются, панель «Сохранить» снова доступна). |

**Правило «что пересчитается».** Западная и ведическая — если менялось время или место; нумерология — если менялось имя/отчество/фамилия; Ба-Цзы — если менялось время (проверяем столп часа).

**Крайние случаи.** В реальном флоу экран открывается только после правки, поэтому изменения всегда есть. При заходе из каталога (без правок) показывается демонстрационный пример — это не продуктовое состояние.

### Л-23 · Пересчёт · анимация
Ключ `recalcRun`. Группа «Данные и настройки».

**Назначение.** Видимое ожидание пересчёта — тот же приём, что первый расчёт карты при онбординге (О-07).

Полоса прогресса + пошаговый список: карта по новым данным → западная и ведическая → Ба-Цзы → нумерология → сверка школ → обновление разборов. Кнопок нет: по завершении экран **сам** открывает Л-18.

**Данные.** Инициирует бесплатный пересчёт карты и всех купленных разборов/документов (см. `idempotency.md`). Сбрасывает `RECALC_SEEN` на старте.

### Л-18 · Пересчитали
Ключ `recalcDone`. Группа «Данные и настройки».

**Назначение.** Показать, что стало другим, и дать открыть обновлённые документы.

**Состав.**
- «Что стало другим» — таблица диффов по затронутым школам (та же сетка, что Л-17) + строка «Глубина: было → стало».
- «Что это значит» — короткое пояснение (с отступом сверху от таблицы).
- «Обновлённые документы» — **каждый пересобранный документ отдельной карточкой**.

| Элемент | Поведение |
|---|---|
| Карточка документа | Тап открывает этот документ (prodResult). У изменённого, но ещё не открытого — **точка «непрочитано»** (как у чата); открытие гасит точку (`RECALC_SEEN`). |
| «Перейти к разборам» | Идём в Разборы · мои разборы (Р-01-2). |

**Что входит в список.** Только документы, затронутые изменением. Построенные по данным другого человека (натальная карта ребёнка, выбор имени для ребёнка) пересчёт данных владельца не затрагивает — в список не попадают.

**При входе в Л-18** пересчёт считается выполненным: `CHANGES` очищается.

---

## Открытые вопросы

- Тестовый пресет (отчество есть, время не указано, база 67%) — для прогона флоу времени. В проде стартовое состояние зависит от реальных данных пользователя; значения глубины на Л-16/Л-17/Л-18 и продуктовых экранах должны считаться, а не быть захардкожены.
- Диффы на Л-18 в прототипе иллюстративные (фиксированные значения). В проде — реальная разница по карте.
