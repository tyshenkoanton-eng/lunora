# Блок: Оплата

**Статус:** ✅ согласован · **Экраны:** К-20…25 (подтверждение, страница оплаты, результат, проверка, копия чека), К-01…19 (касса · путь платежа), К-09…15 (платежи и чеки), Х-01/Х-03/Х-04 (сбои), сообщения бота Б-09/10/17
**Связанные доки:** `payment-pdf-flow.md`, `receipts.md` (чеки, фискализация), `idempotency.md` (идемпотентность, холд/списание), `refunds.md`.

Платёж — самый чувствительный контур ниши: главный барьер покупателя и есть недоверие к оплате. Принцип: **холд при оплате, списание в момент оказания услуги**, и честное поведение во всех сбоях.

---

## Подтверждение и оплата (К-20…К-25)

| Экран | Код | Назначение |
|---|---|---|
| Подтверждение | `К-20` payConfirm | сводка заказа перед оплатой; варианты `К-20-1…4`: обычный / уже куплен / оператор недоступен / платёж обрабатывается |
| Страница оплаты | `К-21` payGate | переход к платёжной форме |
| Оплата подтверждена | `К-22` payOk | успех |
| Проверяем оплату | `К-24` payWait | идёт проверка статуса |
| Оплата не прошла | `К-23` payErr | отказ |
| Копия чека | `К-25` payContact | куда прислать чек: `К-25-1` в Telegram / `К-25-2` на почту |

## Касса · путь платежа (К-01…К-19)

Полный путь через внешнюю платёжную форму и приложение банка, со всеми развилками возврата.

| Код | Ситуация |
|---|---|
| `К-01` | уход из приложения в кассу |
| `К-02` | страница оплаты |
| `К-03` | приложение банка |
| `К-04` | оплата прошла |
| `К-05` | ждём банк |
| `К-06` | не вернулся в приложение |
| `К-07` | банк отклонил |
| `К-08` | вернулся через час |
| `К-18` | платёж пока не найден |
| `К-19` | нашёлся при проверке |

🔑 Ключевой риск — «ушёл оплачивать и не вернулся» / «заплатил, а подтверждение не дошло». Все эти состояния подаются так, чтобы человек понимал: деньги в безопасности, статус проверяется.

## Сбои (`Х-01`, `Х-03`, `Х-04`)

| Экран | Ситуация | Ключевое |
|---|---|---|
| `Х-01` payFail | банк отклонил | «Деньги не списаны» — благодаря холду это правда |
| `Х-03` stWebhook | оплата прошла, подтверждение не дошло | ⚠️ **не выглядит ошибкой**: платёж прошёл, идёт обработка |

## Ключевые правила (реализовать точно)

- **Холд, не списание, при оплате.** Списание — в момент выдачи результата (совпадает с оказанием услуги; `idempotency.md`).
- **Условия сделки показаны до оплаты** (на экране глубины prodDepth, ст. 10 ЗоЗПП), не в документе.
- **Идемпотентность:** повторная оплата/двойное списание ловятся и возвращаются **до** обращения пользователя.
- **Чек** выставляется по применимой схеме (НПД/ККТ), доставляется в Telegram или на почту.
