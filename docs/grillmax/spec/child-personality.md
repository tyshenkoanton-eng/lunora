# Полный разбор личности ребёнка — спека блока

**Статус:** ✅ глубокая. Описывает блок так, как он собран в прототипе
(`wireframes/02-report.html`, бейдж от v679).
**Что это:** платный разбор в витрине «Ребёнок» (`shopChild`, Р-18): полный
разбор личности ребёнка по четырём школам плюс слой «вы и ребёнок» —
сопоставление карты ребёнка с картой пользователя.

Смежные продукты той же группы «Ребёнок» — «Подбор имени» (`childName`,
Р-09-10) и «Проверка имён» (`childCheck`, Р-09-11) — здесь не описываются:
это отдельные нумерологические услуги. Эта спека про `child` (личность).

---

## Карта блока

Один продукт `child`, цена 1 490 ₽. Конвейер как у остальных разборов
(ключи экранов прототипа): `prodPage` (витрина) → `prodData` (форма по
этапам) → `prodDepth` (проверка) → `prodBuild` (сборка) → `prodResult`

## Концепция

Два слоя в одном разборе:

1. **Личность ребёнка по четырём школам** — один в один с личным разбором
   пользователя (западная и ведическая астрология, Ба Цзы, нумерология),
   со своим вводом (ФИО, место, дата, время).
2. **Слой «вы и ребёнок»** — сопоставление карты ребёнка с картой
   пользователя (из профиля). Односторонний: советы адресованы родителю.
   **Без вердикта пары и без баллов** (это не совместимость): нельзя
   сказать «вы с ребёнком несовместимы». Тип отношений фиксирован
   «родитель-ребёнок», шага выбора типа нет. Сопоставление используется
   только для объяснения трений и родительских советов.

Это и есть главное отличие продукта: без слоя сравнения с родителем
пользователь мог бы просто посчитать карту ребёнка отдельно. Поэтому
сравнение заявлено уже в лиде витрины.

---

## Витрина (`prodPage`, Р-09-9)

Единый каркас витрины разборов, контент из `PROD.child`.

- **Лид** (два абзаца): четыре школы и что узнает родитель; второй абзац —
  про сопоставление разбора ребёнка с разбором пользователя.
- **«Что вы узнаете»** — семь пунктов: Характер; Сильные стороны и слабые
  места; Способности и склонности; Учёба и занятия; Как с ним общаться;
  Вы и ребёнок; Как он будет меняться.
- **«Что понадобится»** (`need`): полное имя, дата, время и место рождения
  ребёнка (время лучше из свидетельства о рождении); данные пользователя
  берутся из профиля.
- **«Как выглядит документ»** (`docPages`) + превью (`docView`, Р-17-11).
- **CTA** «Рассчитать» → форма.

Копирайт без «командных» формулировок, без обещаний-приговоров про
развитие («перерастётся», «останется навсегда»), без «не X, а Y» в
первом пункте.

---

## Форма (`prodData`, Р-10-9 … Р-10-9-4)

Собрана по образцу онбординга (О-02…О-05): многошаговый мастер со
степпером и живым баром глубины внизу над кнопкой. Шаг в `CH_STEP`,
данные в `CH` (та же форма, что `OB`).

**Этапы** (`CH_STEPS`): Ребёнок → Место → Дата → Согласие.

- **Ребёнок (chstep 0).** Полное имя (иконка info → шторка **Ф-08**),
  отчество, фамилия, пол. «Дальше» неактивна без имени.
- **Место (chstep 1).** Поле города как в **О-03**: ввод подгружает базу
  городов (`CITIES`), выбор из списка заполняет и поднимает глубину.
  Ссылка «Знаю точный адрес рождения» до ввода города не даёт заполнить и
  показывает «Сначала укажите город рождения», после города открывает
  поле адреса. «Дальше» неактивна без города.
- **Дата (chstep 2).** Дата рождения и время с четырьмя уровнями точности
  (Точно / ± 30 мин / ± 3 часа / Не знаю). «Дальше» неактивна без даты.
- **Согласие (chstep 3).** Чекбокс согласия на обработку данных ребёнка;
  «Продолжить» неактивна, пока галочка не проставлена (переход через
  собственный атрибут `data-chgo`, не `data-go`).

**Бар глубины.** На шагах ввода (0–2) сверху/внизу бар «Глубина расчёта»
со значком info → шторка **Ф-12**; на шаге согласия бара нет. Процент
считает **единый движок** `depthPct(data)` с общей таблицей весов `DW`
(та же, что в онбординге), чтобы глубина нигде не разъехалась. Разбивка
«Что учитывается» — `depthSheet(data)` (общая с онбордингом).

**Сброс.** Свежий вход в форму (через витрину `prodPage` или из каталога)
начинает с первого шага и с чистых данных (`CH_INIT`); переходы шаг↔шаг и
форма↔проверка данные сохраняют. Прямой вход на конкретный шаг из каталога
ставит `CH_STEP` из `s.chstep` (как `cstep` у совместимости).

---

## Проверка данных (`prodDepth`, Р-11-9)

- **Данные.** Наследуются с формы (`CH`). При прямом входе из каталога
  (данных нет) подставляется полный пример (`childDepthData` → `CH_DEF`).
- **Блок данных** — поля с подписями: Полное имя, Дата рождения, Место
  рождения.
- **Глубина.** Полоса с процентом и значком info; если не 100% — мягкая
  строка «Данные всегда можно дополнить, карту пересчитаем бесплатно».
- **Переход.** «Перейти к оплате» → общий конвейер оплаты/сборки.

## Результат (`prodResult`, Р-14-9)

Оформлен как профиль (Л-01а, вкладка «Темы»), а не как один длинный
документ.

- **Заголовок** «Полный разбор личности ребёнка» (не дублирует ФИО).
- **Блок данных ребёнка** — поля с подписями: Имя ребёнка, Дата рождения,
  Место рождения (без возраста и без «Тип разбора»).
- **«Коротко»** — вывод Луноры; прямо сказано, что школы видят ребёнка
  по-разному.
- **Карточки тем** с иконками (семь тем) + карточка **«Данные расчёта»** с
  иконкой в том же списке.
- **Футер** — «Скачать PDF» и «Переслать документ».

Нижняя панель навигации приложения на экранах разбора ребёнка (результат,
темы, данные расчёта) скрыта, чтобы документ читался чисто.

## Экран темы (`chCharacter` … `chChange`, Р-14-9-1 … Р-14-9-7)

Компоновка как Л-02 (взрослая тема). Данные в `CHILD_TDATA`.

1. **Трактовка Луноры** (`luna-block`): вывод + «Где школы расходятся»
   (если есть спор) + «Как будет меняться» (взгляд вперёд).
2. **Источники** (`divider`): блок на каждую школу, которая считает эту
   тему (`sch`), со своим описанием и кнопкой «Прочитать подробно»
   (ведёт на «Данные расчёта»). Молчащие по теме школы (`silent`) помечены
   «молчит».
3. **«Что с этим делать»** (`todo`) — родительские советы по этой теме.
4. **Футер** — «Поделиться разбором» и блок «Остались вопросы? →
   Перейти в чат».
5. **Следующая тема** / с последней — «Вернуться к разбору».

Матрица «тема × школа» (какие школы говорят по теме, пустая клетка =
молчит):

| Тема | Зап. | Вед. | Ба Цзы | Нум. |
|---|---|---|---|---|
| Характер | да | да | да | да |
| Сильные и слабые | да | — | да | да |
| Способности | да | да | да | да |
| Учёба и занятия | да | да | да | да |
| Как общаться | да | да | да | — |
| Вы и ребёнок | да | — | да | да |
| Как будет меняться | да | да | да | — |

## Данные расчёта (`childCalc`, Р-14-9-8)

Отдельный экран, как «Данные расчёта» в профиле. Блок данных ребёнка
(поля с подписями, плюс строка «Время рождения: 06:40, UTC+4») и таблица
по школам: какие положения, столпы и числа взяты, строка «Точность».
Открывается карточкой с лендинга и кнопками «Прочитать подробно» в темах.

## Прогноз

Разбор направлен вперёд, но без жёсткого предсказания судьбы.

- **Берём:** развитие и склонности, тайминг и возрастные периоды («Как
  будет меняться»), когда что обычно легче или труднее.
- **Не берём:** смерть, тяжёлые болезни, трагедии, тёмные «переломы
  судьбы». Трудное подаётся конструктивно.
- **Формулировки** без точных сроков («обычно легче/труднее»), без выводов
  о здоровье. Нехватка числа 4 в квадрате читается как усидчивость и
  порядок, не как здоровье.
- **Оговорка** приведена в соответствие: описываем склад и его развитие,
  это ориентир, не диагноз; «не предсказываем» не пишем.

## Правила и расчёт

- **Школы расходятся — это показано.** Фраза «сходятся все четыре школы»
  не используется: расхождение между школами подаётся как плюс продукта
  (видно, чем системы отличаются).
- **Данные.** Ребёнок — свой ввод; пользователь — из профиля. Блок «вы и
  ребёнок» строится сопоставлением двух карт.
- **Нумерология** — квадрат Пифагора по дате рождения (как в
  нумерологической школе прототипа). Рабочие числа даты дают клетки
  квадрата (у примера Софьи: 8 три раза, 9 дважды, пусто 3, 4, 7).
- **Единый движок глубины** — `depthPct`/`depthSheet` с общей таблицей
  `DW`; онбординг и форма ребёнка считают по одной таблице.

**Требование к движку: историческая зона.** Часовой пояс берётся
исторический на дату рождения, а не текущий (для Волгограда в 2019 —
UTC+4). От зоны зависят асцендент и дома.

---

## Решения, принятые при реализации

1. **Результат как профиль, а не один документ.** Темы — отдельные
   экраны, список с иконками на результате. Навигация повторяет профиль
   (Л-01а → Л-02).
2. **Экран темы как Л-02.** Трактовка Луноры → Источники по школам с
   «Прочитать подробно» → «Что с этим делать» (в разрезе ребёнка) → футер.
3. **Форма как онбординг.** Многошаговый мастер со степпером, живой бар
   глубины на общем движке, шаг места с базой городов и «точным адресом».
4. **Прогноз по максимуму без жести** (см. раздел «Прогноз»).
5. **Пример Софьи сверен по карте.** 9 мая 2019, 06:40, Волгоград, UTC+4:
   асцендент в Близнецах (не восходящий Телец), господин дня Бин
   (Ян-Огонь, не Инь-Земля), Луна западная в Раке и ведическая в Близнецах
   (накшатра Ардра). Цифры иллюстративны, финал за движком.
6. **Данные блоки с подписями.** Формат «поле с подписью» (Имя / Дата /
   Место) распространён на результат, проверку и документы совместимости и
   PDF-разбора.

---

## Крайние случаи

- **Нет времени/места.** Разбор собирается по дате, на проверке мягкое
  предложение дополнить данные, глубина ниже. Жёстко время не требуем.
- **Прямой вход из каталога** на проверку/результат/тему без ввода:
  подставляется пример (Софья).
- **Школа молчит по теме** — в теме явный блок «молчит», в матрице пустая
  клетка.

## Открытые вопросы

1. Отдельный экран на каждую пару «школа × тема» (как у взрослого «Прочитать
   подробно» открывает полный разбор школы по теме). Сейчас кнопка ведёт на
   «Данные расчёта»; полного слоя (28 экранов) пока нет.
2. Финальные числа и конфигурации — сверить с движком и с астрологом/
   нумерологом (пример Софьи построен по упрощённым формулам).
3. Мёртвый `PROD.child.doc` (старый длинный документ, нигде не рендерится)
   убрать при чистке.
4. Контент тем для реального диапазона возрастов (пример — семилетний
   ребёнок).
