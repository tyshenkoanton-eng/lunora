# Блок: Разборы и покупка

**Статус:** ✅ согласован · **Глубина:** полная · **Экраны:** Р-01 (shop), Р-02…04, Р-09…14 (конвейер), Р-15/16/17 (документ), Р-05…08 (подарки), Ф-04; бот Б-08/15/16
**Связанные доки:** `product-flows.md` (содержание 8 документов), `payment-pdf-flow.md`, `idempotency.md`, `depth-model.md`, `agreement-rules.md`.

Платный контур. Все продукты проходят через **один конвейер из 6 экранов**, который рендерится из конфига продукта. Добавить продукт = добавить запись в конфиг, экраны не трогаются.

---

## Конфиг продукта (контракт `PROD[ключ]`)

Каждый продукт — запись с полями. Конвейер читает их и собирает экраны.

| Поле | Тип | Где используется |
|---|---|---|
| `t` | заголовок | все экраны |
| `price` | цена строкой | prodPage, prodDepth, prodPay |
| `crumb` | крошка (раздел) | prodPage |
| `access` | `'вопросы'`/`'сутки'`/отсутствует | **ветвление**: есть → доступ к чату (кнопка «Купить»); нет → разбор-документ (кнопка «Рассчитать») |
| `lead` | лид-фраза | prodPage |
| `sell[]` | `[[заголовок, текст]…]` | «Что внутри» |
| `need` | строка | «Что понадобится» |
| `fields[]` | `[[label, value, required, hint?]…]` | prodData (**если пусто — экран данных пропускается**) |
| `depth` | строка `'67%'` или `'—'` | prodDepth (полоса глубины) |
| `depthNote` | предупреждение | prodDepth |
| `build[]` | этапы сборки | prodBuild (анимация) |
| `doc` | HTML структуры результата | prodResult (тело документа) |
| `res`, `resPhrase` | заголовок и фраза результата | prodResult |
| `file` | `{name, size, pages}` | prodResult/docView (для PDF-продуктов) |

**Продукты в конфиге:** `q3` (три вопроса), `day` (сутки) — доступ к чату; `compat`, `child`, `childName`, `year`, `rename`, `pdf`, `date`, `dateB` — разборы-документы. `CUR` — ключ текущего продукта.

## Р-01 · Витрина (`shop`)

Переключатель вкладок (`SHOPTAB`): **Что считаем** (`Р-01-1`, list) / **Мои разборы** (`Р-01-2`, docs).

| Вкладка | Содержимое |
|---|---|
| Что считаем | четыре плитки пропорциями карт: Про меня / Про людей / Разбор даты / Подарить. Цены **показываются**. |
| Мои разборы | купленные документы по разделам, детерминированные названия (имя, диапазон дат, «было → стало»). Пусто: «Здесь пока пусто» + переход к тому, что считаем. |

Плитки → страницы категорий Р-02 (Разговор), Р-03 (Про меня), Р-04 (Про людей) → выбор продукта → конвейер.

🔑 **Купленное в списке показывается как купленное.** Карточка «PDF вашей карты» в Р-03 (Про меня) после покупки гаснет: вместо цены «Куплен · в разделе „Мои разборы“», тап ведёт в «Мои разборы» (`data-godocs`), а не на оплату. Это снимает единственный незащищённый вход на payConfirm у владельца PDF (см. `payment.md`, К-20-2).

⚠️ **Вкладка запоминается:** из документа «назад» ведёт в «Мои разборы», а не в «Что считаем».

## Конвейер (Р-09…Р-14)

Шесть экранов, все читают `PROD[CUR]`. Число шагов в крошке: `fields.length ? 3 : 2`.

### Р-09 · Страница разбора (`prodPage`)
Крошка · заголовок · лид · «Что внутри» (из `sell`) · «Что понадобится» (`need`) · кнопка-пример (`access` → «Посмотреть, как отвечает» → chat; иначе → «Открыть пример разбора» → docView preview) · главная кнопка **«Купить/Рассчитать · {price}»** → prodData (если есть поля) или prodDepth. Приписка: «Оплата после того, как увидите глубину. Оплачивая, принимаете оферту».

### Р-10 · Данные (`prodData`) — только если `fields.length`
Крошка «шаг 1 из 3» · поля из `fields` (необязательные помечены «— если знаете»; поле города — с автодополнением). Для `compat`/`child` — **галочка о праве передать чужие данные**. Кнопка «Посчитать» → prodDepth. Без полей экран пропускается (prodPage → prodDepth).

### Р-11 · Расчёт / глубина (`prodDepth`)
Крошка «шаг N-1 из N» · заголовок (`access`→«Что вы получаете» / иначе «Карта посчитана») · **полоса глубины** (если `depth≠'—'`) · предупреждение `depthNote` · ориентирующий блок (различается: сутки / вопросы / разбор — что открывается и что ещё не посчитано) · **условия сделки** (различаются по `access`: доступ возвращается пока не использован / готовый разбор вернуть нельзя, но переделаем при ошибке) · ссылки Оферта · Согласие · кнопка **«Оплатить {price}»** → prodPay.

⚠️ **Глубина и условия сделки — до оплаты** (ст. 10 ЗоЗПП), не в документе.

### Р-12 · Оплата (`prodPay`)
«Ждём оплату» · продукт · цена · «Мы всё сохранили, вернётесь через час или неделю — расчёт ждёт» · **поле кода сертификата** · «Я оплатил» → prodBuild · ссылка на поддержку с номером заказа. (В прототипе есть демо-кнопка «Показать экран сбоя» → payFail.)

🔑 **Холд, не списание.** Деньги списываются при выдаче результата.

### Р-13 · Сборка (`prodBuild`)
«Собираю ваш разбор» · этапы из `build` (анимированные: ✓ сделано / ◷ текущий / · впереди) · «Обычно меньше минуты, можно закрыть — пришлём» · «Готово →» → prodResult.

### Р-14 · Результат (`prodResult`)
Заголовок `res` · фраза `resPhrase` · файл (если `file` — большая карточка PDF) · **тело документа** (`doc`) · футер: `access` → «Спросить →» / «К разговору»; иначе → «Скачать PDF» / «Переслать документ». Варианты `Р-14-1/2` обычный / данные изменились (stale после пересчёта).

🔑 **Момент списания = момент выдачи** (видно в логах провайдера). Списание при открытии результата.

### Ф-04 · Шторка «сохранить файл» (`saveSheet`)
Ключ `prodResult`. Сохранение/шеринг готового файла.

## Подарки (Р-05…Р-08)

`Р-05` shopGift · `Р-06` giftCard (не активирован) · `Р-07` giftUsed · `Р-08` giftRefund.

**Правила.** Дарится **конкретный продукт**, не сумма. **Получатель вводит свои данные сам** (чужие ПД от покупателя не попадают). **Сертификат гасится после завершения ввода**, не при открытии ссылки. Срок 12 мес, возврат в любой момент на исходный инструмент. **Поле кода — во всех платных флоу** (prodPay).

## Ключевые правила (реализовать точно)

- **Data-driven конвейер:** экраны не знают про конкретные продукты, всё из `PROD`. Новый продукт = новая запись.
- **Ветвления:** `access` (чат vs документ), `fields` (есть ли экран данных), `depth==='—'` (скрыть полосу), `compat/child` (галочка согласия на чужие данные).
- **Холд → списание при выдаче**, условия до оплаты, идемпотентность (`idempotency.md`).
- **Числовые меры одной школы — со знаменателем школы** (напр. гуна-милан «24 из 36 по ведической шкале»), **никогда не процент совместимости и не полоса заполнения** (жёсткий запрет, см. конфиг `compat`).
