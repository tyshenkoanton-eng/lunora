# Блок: Онбординг

**Статус:** ✅ согласован · **Глубина:** полная · **Экраны:** О-01…О-07, В-01, Б-01/Б-02, Ф-03, Ф-08/Ф-09/Ф-10/Ф-12; показ П-01…04 — `spec/profile.md`
**Связанные доки:** `onboarding-flow.md`, `depth-model.md`, `agreement-rules.md`, `safety-rules.md`.

Путь от первого касания до готового разбора. Самый хрупкий участок: онбординг стоит **перед** ценностью — просит и ничего не даёт. Каждый экран решает одну задачу, объясняет, зачем спрашивает, и видимо прибавляет к глубине.

---

## Состояние онбординга (`OB`)

Все шаги пишут в одну модель; поля восстанавливаются при возврате на любой шаг.

| Поле | Что | Умолчание в прототипе | В проде |
|---|---|---|---|
| `name` | имя | «Антон» | из Telegram `first_name` |
| `fam` | фамилия | «Тыщенко» | из Telegram `last_name` |
| `pat` | отчество | пусто | пусто |
| `sex` | пол `ж`/`м` | **`ж` (предзаполнен)** ⚠️ см. вопрос ниже | решение по `depth-model.md` |
| `city` | город | пусто | — |
| `addr` | адрес | пусто | — |
| `d/m/y` | дата | пусто | — |
| `h/i` | время | пусто | — |
| `prec` | точность времени `t/p/r/n` | `p` (± 30 мин) | — |
| `consent` | согласие на ПД | false | — |

## Глубина расчёта (формула)

Полоса глубины появляется на О-03 и живёт до конца онбординга. Значение — сумма весов заполненных полей (`depth-model.md`, функция `obPct`):

| Поле | Вклад |
|---|---|
| имя | 5 |
| фамилия | 7 |
| отчество | 5 |
| пол | 5 |
| город | 8 |
| адрес (только если есть город) | +3 |
| дата (день+месяц+год) | 37 |
| время, если указано и `prec≠n` | +20 (для `prec=r` «± 3 часа» → **+14**) |
| время точное (`prec=t`) | ещё +10 |
| **Итого максимум** | **100** |

Вклад времени по точности (совпадает с блоком пересчёта): точное **+30**, ± 30 мин **+20**, ± 3 часа **+14**, «не знаю» **+0**.

## Вход

| Код | Экран | Поведение |
|---|---|---|
| `О-01` obStart | Карточка бота до запуска | имя, @-адрес, **видео-автоплей** результата, одна строка описания. Одно действие — «ЗАПУСТИТЬ». Описание называет, **что** получит («карта по четырём школам сразу, бесплатно и целиком»), не как устроено. |
| `Б-01` | Первое сообщение бота | приветствие, что сделаем и в чём отличие, что понадобится и сколько займёт, кнопка «Построить карту» → Mini App. |
| `В-01` welcome | Приглашение · страница по ссылке | лендинг для пришедших по реферальной ссылке. |
| `Б-02` | Бот · вход по приглашению | ветка бота для приглашённого. |

⚠️ **«ЗАПУСТИТЬ» обязательно.** Без запуска бот не имеет права присылать сообщения (ежедневный прогноз, возврат, доставка документов). Открыть Mini App в обход бота нельзя (`safety-rules.md`).

## Шаг 1 · О-02 Знакомство (`obName`)

Индикатор 4 шагов (stepper) · «Давайте познакомимся» · поля · полоса глубины · «Дальше».

| Элемент | Поведение |
|---|---|
| Поле «Полное имя» (`i` → Ф-08) | Предзаполнено из Telegram; редактируемое. Идёт и в расчёт нумерологии. |
| Поле «Отчество» | Необязательное; плейсхолдер «Введите ваше отчество». |
| Поле «Фамилия» | Предзаполнено; необязательное. Подсказка: с фамилией и отчеством нумерология подробнее. |
| Сегмент «Ваш пол» (`i` → Ф-09) | Женский / Мужской. |
| «Дальше» | **Активна только при заполненном имени** (`gate: OB.name`). → О-03. |

⚠️ **Пол обязателен для расчёта** (ведическая, Ба-Цзы), не для текста — потому на первом шаге. Просьба свериться с документами про буквы ФИО — **не здесь**, а при дополнении в настройках (сейчас человек не знает, зачем нам его буквы).

**Подсказки (шторка infoSheet):** Ф-08 зачем полное имя, Ф-09 зачем пол.

## Шаг 2 · О-03 Место рождения (`obPlace`)

«Где вы родились?» · город с подсказками · ссылка «Знаю точный адрес» · полоса глубины · «Дальше» / «Назад».

| Элемент | Поведение |
|---|---|
| Поле «Город» | Автодополнение (`data-sug=city`). Выбор из подсказки пишет `OB.city`, оживляет глубину. |
| «Знаю точный адрес рождения» | Раскрывает блок адреса. **До выбора города** показывает ошибку «Сначала укажите город рождения» (`obAddrErr`) и не раскрывает. |
| Поле «Адрес» | Автодополнение по улице; `+3%` к глубине (только при городе). |
| «Дальше» | **Активна только при выбранном городе** (`gate: OB.city`). → О-04. |

🔑 Блок адреса скрыт, пока нет города (изменения идут вниз по экрану). 🔑 Полоса глубины появляется здесь и живёт до конца.

**Состояние «город не найден»** — ручной ввод координат / ближайший крупный город (открытый вопрос, не отрисовано).

## Шаг 3 · О-04 Дата рождения (`obDate`) — самый тяжёлый

Дата (день/месяц/год колёсами) · время (час/минуты колёсами) · **4 сегмента точности** · глубина · «Дальше».

| Элемент | Поведение |
|---|---|
| Колёса д/м/г, ч/мин (`data-wheel`) | Тап открывает колесо выбора значения — шторку **Ф-03** (`pickSheet`). |
| Сегменты точности (`obPrec`) | `О-04-1` Точно / `О-04-2` ± 30 мин (**предвыбран**) / `О-04-3` ± 3 часа / `О-04-4` Не знаю. При «Не знаю» (`prec=n`) **поля времени скрываются**. |
| «Дальше» | **Активна при полной дате** (день+месяц+год); время **необязательно** (`gate: obDateFull`). → О-05. |
| Подсказка под кнопкой | Пока дата не полная: «Заполните дату — без неё карту не построить». |

⚠️ **Сегменты над полем** (при смене меняется то, что ниже касания). ⚠️ **«± 30 мин» предвыбрано** — предвыбор ошибается в безопасную сторону. Без времени теряется ~треть разбора (дома, восходящий, столп часа) — массовый случай. Подсказка `Ф-10` — важность времени.

Год по умолчанию в колесе — **1986** (середина ядра ЦА, `03_audience.md`). Этот же паттерн точности переиспользован в Личных данных (`spec/personal-data-recalc.md`).

## Шаг 4 · О-05 Согласие (`obConsent`)

Объяснение зачем · строка про удаление по требованию · **галочка** · строка о старте расчёта · глубина · «Начать расчёт».

| Элемент | Поведение |
|---|---|
| Галочка согласия (`data-consent`) | Пишет `OB.consent`. Это **сохраняемое поле**, как имя/дата — восстанавливается при возврате. |
| Ссылка на документ | Подсвечена **сама формулировка согласия** (не слово «здесь»). → doc-consentNew. |
| «Начать расчёт» | **Активна только при галочке** (`gate: OB.consent`). → О-06. |

⚠️ Согласие — **отдельный документ**, не часть оферты (156-ФЗ, `agreement-rules.md`). Оферта акцептуется оплатой — здесь принимать не нужно, покупать нечего.

## О-06 Проверьте данные (`obCalc`)

Имя · дата и время с допуском · место · ссылка «изменить». Варианты `О-06-1/2` (полные/неполные данные).

| Состояние | Поведение |
|---|---|
| Готово (есть имя, город, дата) | сводка + «Начать расчёт» (→ О-07) + «Изменить данные» (→ О-02). |
| Не готово (нет имени/города/даты) | «Чтобы построить карту, нужны имя, место и дата» + «Заполнить данные» (→ О-02). |

🔑 **Подтверждение без отдельного шага** — встроено в экран расчёта, не выделено в пятый. ⚠️ Правка здесь **не считается в лимит правок** (человек ещё ничего не получил).

## О-07 Расчёт (`obRun`)

Сводка данных · полоса прогресса · пошаговый список с осмысленными подписями (строим карту неба → западная → ведическая → Ба-Цзы → нумерология → сверка школ → собираем разбор) · кнопка «Открыть мою карту» (активируется по завершении).

Анимация: 7 шагов по ~1,5 с, полоса едет к концу текущего шага; по готовности кнопка → показ (П-01). 🔑 Расчёт как шоу (конкретная дата и действие, не «загрузка»).

| Состояние | |
|---|---|
| Дольше 15 секунд | «Считаем дольше обычного», не бросать |
| Ошибка движка | «Попробуем ещё раз» + автоповтор |

Этот приём видимого ожидания переиспользован при пересчёте (Л-23).

## ⚠️ Требует подтверждения (расхождение доков)

**Предвыбор пола.** В прототипе `OB.sex` предзаполнен **женским** (`ж`), и `depth-model.md` фиксирует это как [РЕШЕНИЕ Антона, 2026-08-26] (экран не должен встречать незаполненным полем; пол виден в профиле, меняется в один тап, пересчёт бесплатный; риск — часть пройдёт мимо не глядя). Но `screens.md` (устар.) говорит обратное: «ничего не выбрано заранее, предвыбор пола — ошибка».

➡️ **Вопрос:** оставляем предвыбор женского (как в прототипе и depth-model) или убираем предвыбор? Спека сейчас описывает предвыбор женского.
