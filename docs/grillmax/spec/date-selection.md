# Выбор лучшего дня (электив) — спека блока

**Статус:** 🟡 в работе. Форма, пикер, подтверждение и образец собраны;
содержание образца условное, витрина ждёт продуктовых решений (см. конец).
Соответствует прототипу (`wireframes/02-report.html`, бейдж от v734).

**Что это:** разбор «Выбор лучшего дня» (`date`, 390 ₽) — поиск самых
благоприятных дней для события в заданном периоде по четырём школам.

**Решение по датам (2026-11):** два сценария разведены.
- **Поиск лучшего дня в периоде** — это разбор-документ (`date`).
- **Разбор конкретной назначенной даты** — в **чате** (отдельного продукта
  `dateB` больше нет; его экраны и запись в «Моих разборах» удалены).
  На витрине продукта сноска-askchat «Уже выбрали дату? Спросите в чате».

Каталог «Разборы» (Р-01-1) ведёт по карточке «Выбор лучшего дня» **сразу на
страницу продукта** (Р-09-13); промежуточного экрана-развилки нет
(`shopDate` удалён).

## Форма (Р-10-13, своя функция `dateData`)

Многошаговая (степпер «Ввод данных / Проверка»), заголовок «Подбор лучшего
дня». Поля по порядку:

1. **Название события** (обязательное, до 80, `DATE_NAME`) — его вводит сам
   пользователь, идёт заголовком в блоке данных.
2. **Описание** (обязательное, до 300 со счётчиком, `DATE_EVT`) — свободный
   текст: что за событие и что важно учесть. По описанию в проде Лунора
   подбирает подходящие дни.
3. **Временной период** — два поля `дд.мм.гггг` через дефис, тап открывает
   шторку Ф-25. Состояние `DATE_FROM`, `DATE_TO`.
4. **Город события** (обязательное, `DATE_CITY`, автодополнение по `CITIES`) —
   **по умолчанию из профиля**, можно изменить. Нужен для удачных часов дня
   (окна времени считаются от местного горизонта). Своя связка
   `data-datecity`, без адресной логики онбординга.

**«Далее» активна**, когда заполнены название, описание, город и обе даты.
Демо для проверки: правый клик по полю подставляет пример.

### Шторка выбора даты (Ф-25, `#datePick`)

Год шевронами → месяц шевронами → сетка чисел, «Готово» фиксирует. Правила:
- **По умолчанию — реальное сегодняшнее число** (`DATE_TODAY` из системной
  даты).
- **Начало не раньше сегодня** (событие в будущем).
- **Окно ограничено месяцем** (`DATE_SPAN=30` → до 31 дня включительно);
  конец не дальше начала + месяц, за пределом дни/месяцы/годы заблокированы.
- **Конец подставляется автоматически** на +2 недели (`DATE_DEFAULT_SPAN=14`)
  при выборе начала; при смене начала держится в окне `[начало, начало+месяц]`.
- В пикере конца выбранный период показан **полосой**: начало и конец —
  точки, дни между — заштрихованы; при выборе более раннего дня полоса
  сжимается.

Открывается и из формы, и из реестра (Ф-25) для согласования.

## Подтверждение (Р-11-13, своя функция `dateDepth`)

Единый формат проверки данных (эталон Р-11-11): «Разбор» + название разбора
+ линия + данные с подписями — **Название, Описание, Город, Период**
(надписи, не редактируются здесь). Кнопка **«Изменить данные»** возвращает
на форму (`prodData`) с заполненными полями (форма рендерится из состояния).

## Результат (Р-14-13, `prodResult`, `doc`)

Формат как у других разборов (ср. Р-14-10): **заголовок = название разбора**
(«Выбор лучшего дня», отдельной фразы-resPhrase нет) → блок данных
(Название, Описание, Город, Период) → «Коротко» → разделы.

Разделы образца:
1. **Коротко** (фиолетовый `luna-block`): лучший день, сколько подходят,
   общая картина периода.
2. **Лучшие дни** (3–5): каждый в нейтральной рамке (`daycard`, не
   фиолетовой), с окном времени и доводами по школам; **личные и общие
   доводы разделены** (личных обычно немного, об этом честно).
3. **Все дни** — таблица: дата, итог словами, отметка по каждой школе
   (на мобильном без колонки «причина»).
4. **Что пропустить** — с разделением «плохо для всех» и «плохо лично для вас».
5. **Как выбрать между днями** — что делать, если лучший день занят.
6. **Как посчитано** — по школам; медленные планеты (Юпитер) идут фоном
   периода, а не доводом по конкретному дню.

**Образец условный.** Содержание по согласованному ревью, но астрология
поставлена для примера (декабрь 2026). Нужно сверить на реальном расчёте
движка: ретроградность Меркурия 17.12.2026 и картину «три хороших дня до
20-го».

## Открытые вопросы (для полной переписи витрины)

По разбору конкурентов (electional / мухурта / Ба-Цзы-календари):

1. **Тип события списком.** Повод определяет, какие показатели главные
   (для свадьбы Венера, для дел Меркурий и Юпитер). Сейчас только свободный
   текст — нужен выбор из списка (договор/переговоры, свадьба, переезд,
   запуск, поездка, покупка, экзамен), а текст останется заметкой. **Из
   списка не берём операцию и лечение** (их выбор нельзя оставлять
   астрологии).
2. **Период: 31 или 60 дней** (у AstroMedha 60). Сейчас 31.
3. **Участники.** Для свадьбы и партнёрских дел — данные второго человека
   (необязательно).
4. **Как соединять школы.** Предложение: каждая школа ставит дню оценку
   словами, «лучший» день — без плохих оценок и минимум с тремя хорошими.
5. **Школы на витрине** не названы (в остальных витринах названы).
6. **Строка «это не гарантия»** на витрине (у серьёзных конкурентов есть).
7. **Таблица всех дней на мобильном** — как показать причину по дню, не
   ломая ширину.

Хорошо уже сейчас: сноска «Уже выбрали дату? Спросите в чате» работает как
аналог бесплатной проверки конкретной даты у конкурентов.
