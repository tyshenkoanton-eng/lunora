# Лунора — пакет для внешнего ревью (v3, 16 ноября 2026)

Третья редакция. Учтены замечания ревью v2 (распространение решений по документам), приняты решения по ценам и провайдеру, добавлены два собственных исследования (правовое и методическое) и архитектурное решение по границам системы.

## Что за продукт (коротко)
Telegram Mini App (и далее MAX, веб, мобильные) — персональный разбор личности по четырём системам сразу (западная и ведическая астрология, Ба-Цзы, нумерология), сведённым в один разбор. Позиционирование — инструмент самопознания на данных о рождении, не эзотерика.

## Честный статус
- **Проработка, UX-прототип, архитектура и спецификации движка — готовы. Разработка не начата.**
- **Прототип** `прототип/02-report.html` имитирует интерфейс и **не считает по-настоящему** (данные зашиты). Экономит время на UX и текстах, не на движке.
- **Библиотека интерпретаций (~2 800 блоков) — почти пуста.** Это главный объём предстоящей работы.
- **Данные в прототипе — демонстрационные** (автор и вымышленные лица). Фискальные маркеры чека стоит замаскировать перед передачей незнакомому рецензенту.

## Что изменилось с v2 (главное для повторного ревью)
1. **Распространены решения по документам** (ревью v2 указало, что они были только в реестре):
   - эфемериды — **Skyfield + JPL DE440** (бесплатно, без лицензии 700 CHF и AGPL-риска) — по всей архитектуре;
   - дома — цельные знаки, полярный порог **66,56°** (не 60°) — в архитектуре, `calc-tables`, `edge-cases`;
   - модель чата — **пакеты запросов** (не суточный таймер): `time_window` убран из архитектуры;
   - смена дня Ба-Цзы — 23:00; телесные выводы о здоровье удалены из прототипа и контракта;
   - позиционирование «согласие школ» переписано (не доказательство).
2. **Единый прайс** — `ПРАЙС.md` (источник истины) + юнит-экономика; цены **подтверждены**.
3. **Два собственных исследования** (`исследования/`): правовое (152-ФЗ, согласие, трансграничная передача, авторские права) и методическое (развилки по школам). Оба **проверены**: методическое — прогоном **12 000 карт**; позиции помечены «подтвердить специалистом при запуске» (юриста и практика зовём к запуску).
4. **Рекомендации метода внесены в движок** — `ENGINE-SPEC §8.4`: независимость школ (ключевое), пороги, авторские правила названы «правило Луноры».
5. **Архитектура границ** — `ДВИЖОК/ADR-002`: три слоя **Клиенты → API → Движок**; клиенты (Telegram/MAX/веб/мобильные) сменные, школы расширяемы, LLM через порт (сейчас **OpenRouter**).
