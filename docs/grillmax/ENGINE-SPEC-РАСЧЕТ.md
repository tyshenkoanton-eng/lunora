### 0.1 Место документа

| Слой | Документ | Отвечает на вопрос |
|---|---|---|
| Состав | `calc-tables.md`, `skeletons.md` §3 | **что** считаем и показываем |

| Голосование | `consensus-map.md` | какие предикаты над сигналами дают ▲ / ▼ |

Критерий «метод закрыт» (B10): для величины заполнена строка **величина → правило → формула или таблица → источник → версия → примеры → golden-кейс**. Строка со словом «выписать» или `[ОТКРЫТО]` означает: величина **не голосует и не даёт выводов**, пока не закрыта.

### 0.2 Четыре принципа

| # | Принцип | Что это значит для разработчика |
|---|---|---|
| П-1 | **Fail closed** | Если величина не вычислима по правилу с источником — движок возвращает `not_computed` с причиной, школа воздерживается. «Примерно» не считаем. `NaN`, пустая строка, значение по умолчанию — запрещены как способ сообщить «не вышло» |
| П-2 | **Авторское называется авторским** | Любой порог, вес, свод или округление, которых нет в первоисточнике, помечен в этом документе «**авторское правило Луноры**», а в сигнале — `rule_origin: lunora`. В «Как это посчитано» такие правила подписаны теми же словами |
| П-3 | **Таблица — это данные с версией** | Каждая таблица традиции лежит в `content/tables/` отдельным файлом с версией, SHA-256, источником (издание, страница) и статусом. Код таблиц не содержит |
| П-4 | **Расчёт не толкует** | Движок отдаёт факты («Марс в обители, +5»), а не выводы («Марс сильный человек»). Классы «сильный / слабый», введённые здесь, — это именованные предикаты над числами, а не интерпретация |

### 0.3 Статусы таблиц и правил

| Статус | Значение | Может ли участвовать в голосовании |
|---|---|---|
| `draft` | выписано в этом документе по общеизвестному изложению традиции; построчно со сканом первоисточника **не сверено** | нет (`can_vote: false`) |
| `verified` | сверено со сканом; в файле таблицы указаны издание и страница, сверяющий, дата | да — если правило из первоисточника |

## 1. Общий контракт

### 1.1 Вход

Движок получает `EngineInput` (`ARCHITECTURE.md` §3.1). Поля, от которых зависит расчёт:

| Поле | Тип | Кому нужно | Если отсутствует |
|---|---|---|---|
| `moment` (`ResolvedMoment`) | интервал(ы) UTC + гипотезы смещения | всем трём школам | расчёт только по дате: см. §1.5 |
| `moment.local_time` | время или `None` | ASC, дома, секта, лагна, бхавы, паду, даши, столп часа | величины, зависящие от времени, — `not_computed: no_birth_time` |
| `place.lat`, `place.lon` | градусы, WGS-84, геодезическая широта | ASC/MC, истинное солнечное время | то же, причина `no_place` |
| `sex` | `f` / `m` | **только Ба-Цзы**: направление да-юнь, звезда супруга; в ведической — Маха-Бхагья-йога | да-юнь — `not_computed: no_sex`. Пол **не угадывается** и не берётся из предзаполнения без подтверждения пользователем |
| `profile` (`MethodProfile`) | §7 | всем | ошибка сборки, не рантайма |

### 1.2 Выход

Каждая посчитанная величина — один или несколько `Signal` по `data-model.md` §1. Поля, которые заполняет движок, и их смысл в этой спецификации:

| Поле `Signal` | Что кладём |
|---|---|
| `system_id` | единый enum `SystemId` = `western` · `vedic` · `bazi` · `numerology` (канон — `API-КОНТРАКТ.md` §2.2/§6; старые имена `western_astrology`/`jyotisha` сняты H11). В этом документе формализованы `western`/`vedic`/`bazi`; `numerology` — в `NUMEROLOGY-RULES.md` |
| `technique_id` | идентификатор величины из этого документа, например `w.dignity.essential` |
| `signal_type` | `position` · `dignity` · `aspect` · `period` · `pillar` · `count` · `interaction` · `setting` |
| `raw_value` | число без округления (долгота в градусах `float64`, балл, момент TT) |
| `normalized_value` | дискретное значение (знак, дом, накшатра, столп, класс) |
| `calculation_rule_id` / `calculation_rule_version` | идентификатор и версия правила из колонок «ID» и «Версия» ниже |
| `input_dependencies[]` | `birth_time`, `birth_place`, `tz_hypothesis`, `sex`, `method_choice` |
| `stability` | `stable` / `range` / `undetermined` / `convention` по `ARCHITECTURE.md` §4.5; наружу (в `Signal` DTO API §2.2) отдаётся только тег, полный интервал — в `ChartSnapshot` |
| **`rule_origin`** | канон (`API-КОНТРАКТ.md` §2.2, `data-model.md` §1): `source` — правило из первоисточника · `lunora` — авторское |
| **`frame`** | канон: `tropical` / `sidereal` / `none` — для всех величин, зависящих от зодиака (B2); для Ба-Цзы/нумерологии — `none` |
| **`can_vote`** | внутреннее поле ядра (за границу API не выходит, §API 2.3): `false`, если правило или таблица ниже статуса из §0.3, либо величина — `not_computed` |

`not_computed` — это тоже сигнал: `normalized_value: not_computed`, `reason`: одно из `no_birth_time`, `no_place`, `no_sex`, `not_applicable_latitude`, `rule_not_formalized`, `out_of_v1`, `table_not_verified`.

### 1.3 Версии

| Объект | Схема версии | Где хранится |
|---|---|---|
| Правило расчёта | semver; `0.x` — до подписи практика, `1.0.0` — после | `calculation_rule_version` каждого сигнала |
| Таблица | semver + SHA-256 файла | `content/tables/<id>@<ver>.yaml`, поле `versions` карты |
| Эфемериды | имя файла + SHA-256 | `versions.ephemeris` |
| Библиотеки (Skyfield, numpy) | точная версия, закреплена в lock-файле | `versions.engine` |
| Профиль метода | `lunora@<semver>` | `method_profile_version` |

Смена любой версии → новая `ChartSnapshot` и отчёт влияния (`ARCHITECTURE.md` §6.7).

### 1.4 Детерминизм

| Правило | Зачем |
|---|---|
| Все долготы — `float64` в градусах, диапазон `[0, 360)`; округление только при отображении | `ARCHITECTURE.md` §3.3 |
| Все интервалы таблиц — **полуоткрытые** `[начало, конец)`: планета ровно на 6°00′00″ Овна принадлежит второму терму, ровно на 30° — следующему знаку | иначе граница зависит от реализации |
| Поиск корня (момент термина, возвращение Солнца, граница накшатры) — бисекция или метод Брента до `abs(Δt) ≤ 1 мс`; результат хранится в TT как число суток `float64` и в UTC с точностью до секунды | воспроизводимость |
| Сравнение «до / после момента» — по TT | UTC до 1972 года не определено (§2.2) |
| Никаких часов, сети, случайности; «сегодня» приходит параметром | `ARCHITECTURE.md` §3.8 |
| Порядок сигналов в списке — лексикографически по `(system_id, technique_id, объект)` | побайтная воспроизводимость |

### 1.5 Что считается без времени рождения

| Школа | Считается (возможно, с `range`) | `not_computed: no_birth_time` |
|---|---|---|
| Западная | знаки планет (Луна — `range`, если за сутки меняет знак), аспекты между медленными планетами, обитель / экзальтация / изгнание / падение | ASC, MC, дома, секта → триплицитет → **эссенциальный балл целиком становится `range`**; акцидентальные достоинства, Жребий, профекции, фирдария |
| Ведическая | раши грах, накшатра Луны (часто `range`) | лагна, бхавы, пада, даши (ошибка начала — до нескольких лет), D9, D10 |
| Ба-Цзы | столпы года и месяца (если сутки не содержат термина), столп дня — `range` из двух значений (последний час суток уходит следующему дню, §5.4) | столп часа; три сигнала силы — `range` или `undetermined`; да-юнь: направление считается, возраст входа — с погрешностью ± 4 месяца |

### 2.2 Момент

**ID** `eph.instant` · **версия** 0.1.0 · **источник:** определения шкал времени МАС; развилка до 1972 года — **авторское правило Луноры**, проверено расчётом.

| Дата рождения | Как строится момент | Почему |
|---|---|---|
| с 1972-01-01 | гражданское время минус смещение пояса = **UTC** → `ts.utc(...)` | UTC с секундами координации определено с 1972 года |
| до 1972-01-01 | гражданское время минус смещение пояса трактуется как **UT1** → `ts.ut1(...)` | до 1972 года гражданское время привязано к вращению Земли; Skyfield при `ts.utc` для этих лет подставляет постоянные «TAI − 10 с», что даёт сдвиг |

Проверка расчётом (Москва, 15 июня, 09:00 «UT»): разница между трактовками `utc` и `ut1`

| Год | Δ момента | Δ ASC | Δ Луны |
|---|---|---|---|
| 1930 | 17,8 с | 2,96′ | 8,8″ |
| 1950 | 13,1 с | 2,18′ | 6,6″ |
| 1960 | 9,0 с | 1,50′ | 5,0″ |
| 1971 | 0,7 с | 0,12′ | 0,4″ |

Ошибка в выборе шкалы съедает весь допуск по ASC (§2.11) для родителей и старших партнёров ЦА. **Golden:** `GE-03`.

### 2.4 ASC и MC

**ID** `eph.angles` · **версия** 0.1.0 · **источник:** сферическая астрономия (Meeus, «Astronomical Algorithms», гл. 12–14); правило для полярных широт — **конвенция, выбранная Лунорой** по тестовому оракулу.

```
θ    = GAST(t)·15° + λ_geo          местное истинное звёздное время, градусы (RAMC)
ε    = ε0(t) + Δε(t)                истинный наклон эклиптики (средний ИАЮ 2006 + нутация ИАЮ 2000A)
MC   = atan2( sin θ , cos θ · cos ε )
ASC  = atan2( cos θ , −( sin θ · cos ε + tan φ · sin ε ) )
если (ASC − MC) mod 360° ≥ 180°  →  ASC = ASC + 180°       # полярное правило
DC = ASC + 180°,  IC = MC + 180°
```

`GAST` берётся из Skyfield (`t.gast`), своя формула звёздного времени не пишется. `φ` — геодезическая широта без приведения к геоцентрической.

| Пример | RAMC | ε | MC | ASC |
|---|---|---|---|---|
| A | 343,31935° | 23,442151° | 11°54′46,0″ Рыб | 11°11′47,8″ Рака |
| B | 60,68963° | 23,443265° | 02°44′54,1″ Близнецов | 10°31′34,6″ Девы |
| C (68,96° N) | 74,22217° | 23,441595° | 15°28′01,0″ Близнецов | 21°55′37,2″ Девы |

🔑 **Полярное правило — не косметика.** На 4 000 случайных моментов при `abs(φ)` от 66,6° до 89,5° формула без последней строки расходится с оракулом ровно на 180° в **30 %** случаев; с ней — совпадает до 0,008″. При цельнознаковых домах переворот ASC меняет нумерацию всех домов, а Мурманск и Норильск входят в обязательные кейсы. Какая из двух конвенций «правильная» — вопрос метода: `[ОТКРЫТО → практик]`, до ответа действует конвенция оракула. **Golden:** `GE-02`, `GE-04`.

Расхождение с оракулом для дат до 2026 года — ≤ 0,002″. Для будущих дат (прогнозы) оно растёт до ~2″ из-за разных прогнозов ΔT — это свойство прогноза вращения Земли, не ошибка.

### 2.5 Дома

**ID** `eph.houses.whole_sign` · **версия** 1.0.0 · **источник:** решение Антона 2026-09-07, D-105 (B11); метод — эллинистическая практика.

```
знак_ASC = floor(ASC / 30°)                       0 = Овен … 11 = Рыбы
дом(λ)   = ( floor(λ / 30°) − знак_ASC ) mod 12 + 1
```

Дом равен знаку целиком; «куспид» цельнознакового дома — 0° знака. MC — точка, а не куспид X дома: отдельный сигнал `w.mc.house` говорит, в каком доме она стоит.

| Пример | Правило в действии |
|---|---|
| A: ASC в Раке → I дом = Рак | Марс и Сатурн (Скорпион) — V дом; Солнце (Водолей) — VIII; Луна (Рыбы) — IX; MC (Рыбы) — в IX доме |
| B: ASC в Деве | Солнце и Венера (Близнецы) — X дом; Луна (Водолей) — VI |
| C: ASC в Деве (после полярного правила) | Юпитер (Лев) — XII дом |

**Плацидус — справочно.** **ID** `eph.houses.placidus` · **версия** 0.1.0 · источник: стандартный итерационный алгоритм по дневной и ночной полудуге.

```
для куспида k:  (11: H=30°, F=1/3)  (12: H=60°, F=2/3)  (2: H=120°, F=2/3)  (3: H=150°, F=1/3)
  α ← θ + H
  повторять до abs(Δα) < 1e−11°:
      δ  = atan( sin α · tan ε )
      AD = asin( tan φ · tan δ )
      α  = θ + H + F · AD
  куспид_k = atan2( sin α , cos α · cos ε )
куспиды 1, 10 = ASC, MC;  5, 6, 8, 9 — противоположные 11, 12, 2, 3
```

| Условие | Результат |
|---|---|
| `abs(φ) ≤ 66,56°` | куспиды считаются; расхождение с оракулом — 0,00002″ при одинаковых θ и ε |
| `abs(φ) > 66,56°` | **все** куспиды Плацидуса — `not_computed: not_applicable_latitude`. Не `NaN`, не «равнодомная вместо Плацидуса». Цельные знаки при этом считаются штатно |
| Порог | константа 66,56° (D-105), не `90° − ε(t)`; вблизи порога `asin` может не существовать — тогда тоже `not_applicable_latitude` |

Примеры: A — XI 17°15′44″ Овна, XII 02°19′02″ Близнецов, II 28°04′03″ Рака, III 17°05′47″ Льва. D (59,94° N) — XI 22°49′02″ Близнецов, XII 00°11′04″ Льва, II 12°45′07″ Девы, III 05°24′35″ Весов. C (68,96° N) — `not_applicable_latitude`. **Golden:** `GE-05`.

### 2.7 Айанамша Лахири

**ID** `eph.ayanamsha.lahiri` · **версия** 0.1.0 · **источник:** Комитет по реформе календаря Индии (1955), значение 23°15′00″ на 21 марта 1956; якорь и способ продолжения — по стандартному варианту тестового оракула (`ENGINE-SOURCES.md` §3.2, вариант № 1).

```
T   = (JD_TT − 2451545,0) / 36525
p_A(T) = ( 5028,796195·T + 1,1054348·T² + 0,00007964·T³ − 0,000023857·T⁴ − 0,0000000383·T⁵ ) / 3600   # градусы, ИАЮ 2006
T0  = (2435553,5 − 2451545,0) / 36525                 # 21 марта 1956, 0h TT
A_mean(t) = 23,2455610° + p_A(T) − p_A(T0)            # СРЕДНЯЯ айанамша
λ_sid = ( λ_trop_видимая − Δψ(t) − A_mean(t) ) mod 360°
```

🔑 **Якорь — 23°14′44,02″, а не 23°15′00,658″.** Каноническое значение 23°15′00,658″ — это айанамша **с нутацией** на эпоху якоря (Δψ = +16,64″). Средняя айанамша на ту же эпоху — 23,2455610°. Кто подставит 23°15′00,658″ в формулу для средней, получит постоянную ошибку 16,6″ — около 30 секунд времени для Луны и до 4 суток в датах даш. Проверено расчётом.

Якорные значения `A_mean` (для самопроверки реализации, расхождение с оракулом ≤ 0,0005″ на 1900–2100):

| Дата (0h TT) | A_mean | В градусах |
|---|---|---|
| 1900-01-01 | 22°27′37,9″ | 22,4605306 |
| 1956-03-21 | 23°14′44,0″ | 23,2455610 |
| 2000-01-01 | 23°51′25,5″ | 23,8570732 |
| 2026-01-01 | 24°13′13,1″ | 24,2203039 |

Примеры: A — `A_mean` = 23,634897°, Δψ = −0,004099° → Луна 341,68891° − (−0,00410°) − 23,63490° = 318,05812° = 18°03′29″ Кумбхи. B — `A_mean` = 23,681815°. D — 23,334737°. **Golden:** `GE-10`.

⚠️ Какой вариант «Лахири» стоит по умолчанию в эталонном сервисе (Jagannatha Hora) — spike П-2 из `ENGINE-SOURCES.md`; значение варианта записывается в каждый golden-кейс.

## 3. Западная школа

**Кадр:** тропический (`frame: tropical`). **Тела метода:** семь классических планет. Уран, Нептун, Плутон — «современный слой»: имеют долготу, дом и аспекты, но **не имеют** достоинств, не управляют знаками, не входят в цепочку диспозиторов.

### 3.2 Секта

**ID** `w.sect` · **версия** 0.1.0 · **источник:** эллинистическая традиция; у Лилли — «дневная / ночная» фигура для выбора управителя триплицитета.

### 3.4 Эссенциальный балл

**ID** `w.dignity.essential` · **версия** 0.1.0 · **источник:** Лилли, CA, «A Table of the Fortitudes and Debilities of the Planets», с. 115 `[сверить страницу]`. Числа — из первоисточника; правила сложения, помеченные ниже, — авторские уточнения.

| Состояние | Балл | Условие |
|---|---|---|
| Обитель | **+5** | планета — управитель знака, в котором стоит |
| Экзальтация | **+4** | планета экзальтирует в этом знаке |
| Триплицитет | **+3** | планета — управитель триплицитета знака **по секте карты** |
| Терм | **+2** | планета — управитель терма своего градуса |
| Фас | **+1** | планета — управитель фаса своего градуса |
| Изгнание | **−5** | знак противоположен обители планеты |
| Падение | **−4** | знак противоположен знаку экзальтации |
| Перегрин | **−5** | ни одного из пяти достоинств (обитель, экзальтация, триплицитет, терм, фас) |
| Взаимная рецепция по обители | +5 | A в обители B **и** B в обители A |
| Взаимная рецепция по экзальтации | +4 | то же по экзальтации |

Правила сложения:

| Правило | Происхождение |
|---|---|
| Достоинства **суммируются** (обитель + триплицитет + терм + фас дают +11) | практика Лилли в разборах карт |
| Изгнание и падение суммируются с малыми достоинствами (Марс в Раке на 3°: −4 +3 +2 = +1) | то же |
| **Перегрин НЕ суммируется** (решено §8.4 Р-3/Р-4): отдельная строка; планета без достоинств в голосовании **молчит**. ▲ — только обитель/экзальтация; ▼ — только изгнание/падение; перегрин — ни ▲, ни ▼ | **правило Луноры** (§8.4 Р-4; подтверждает практик) |
| Рецепция перегрин **не снимает** | **авторское уточнение Луноры**, `[ОТКРЫТО → практик]` |
| Смешанные рецепции (обитель ↔ экзальтация) не учитываются | у Лилли в таблице их нет |

Движок отдаёт **два числа**, а не одно:

| Сигнал | Состав | Назначение |
|---|---|---|
| `w.dignity.essential_own` | пять достоинств + изгнание + падение + перегрин, **без рецепций** | **переменная порогов** карты консенсуса («Сатурн ≥ 4 баллов») |
| `w.dignity.essential_lilly` | то же + рецепции | таблица достоинств на экране школы |

Почему пороги стоят на `essential_own`: только для него доказуемо (перебором таблиц §3.3), что **обитель или экзальтация ⇒ балл ≥ 4**, а **изгнание или падение ⇒ балл ≤ 2**. С рецепциями это свойство ломается (Сатурн в Овне во взаимной рецепции с Марсом в Козероге набирает до +3), и условия ▲ и ▼ могут сработать вместе — нарушение M-6.

**Примеры** (карта A, дневная):

| Планета | Положение | Разбор | `essential_own` |
|---|---|---|---|
| Марс | 11°48′ Скорпиона | обитель +5; триплицитет воды +3; терм Скорпиона 6–14 — Юпитер; фас II — Солнце | **+8** |

### 3.6 Классы силы и порог голосования

**ID** `w.strength_class` · **версия** 0.1.0 · **авторское правило Луноры** (пороги взяты из `consensus-map.md`; в первоисточнике есть таблица баллов, но нет порогов «сильный / слабый»).

```
E = w.dignity.essential_own
▲ (сильный)  ⇔ флаг: обитель ИЛИ экзальтация
▼ (слабый)   ⇔ флаг: изгнание ИЛИ падение
иначе (в т. ч. перегрин)   → школа молчит
```

✅ **РЕШЕНО (§8.4 Р-3/Р-4).** ▲/▼ задаются **флагами достоинства**, а не порогами `E ≥ 4` / `E ≤ 2`: порог `E ≥ 4` достигается и без обители (триплицитет +3, терм +2). Перегрин — **отдельная строка, не суммируется** с изгнанием/падением и голоса не даёт. Прежняя запись порогов (`E ≥ 4`, `E ≤ 2`, `E ≤ 1` для К-03/К-04) — `superseded_by §8.4 Р-3/Р-4`; балл `E` остаётся справочным.

Слова «сильный / слабый» в условиях `consensus-map.md` (К-06, К-07, К-11, К-13, К-17, К-18) читаются **только** так. Акцидентальный балл в голосовании v1 не участвует.

|---|---|---|---|---|
| Солнце | 16 % | 82 % | 2 % | 70 % |
| Луна | 17 % | 78 % | 4 % | 66 % |

Решение — §8.4 Р-1: знаковые ведические условия в общем кадре не голосуют, а бхавы, даши, накшатры от кадра голосования не зависят и голосуют в кадре школы.

### 5.2 Два времени: конвенция (T-7)

**ID** `bz.time_convention` · **версия** 0.1.0 · **решение D-106**.

| Что определяем | По какому времени | Как именно |
|---|---|---|
| **Год и месяц** (до или после термина) | **абсолютный момент** | сравниваются момент рождения и момент термина в TT. Это то же самое, что сравнить оба момента, выраженные в среднем солнечном времени меридиана 120° E (UTC+8, в нём публикуются термины) |
| **День и час** (столп дня, столп часа) | **истинное солнечное время места рождения**, §2.8 | двухчасовая стража и дата берутся по TST |

Почему конвенции разные и это не ошибка: термин — астрономическое событие, единое для всей Земли; вопрос «наступил ли уже ли-чунь» не зависит от того, где стоит роддом. Стража — положение Солнца относительно местного меридиана; она местная по определению. Альтернативная практика — сравнивать показание местных истинных часов с пекинским показанием момента термина — сдвигает границу года на разность долгот (для Волгограда — на 5 часов) и здесь **не применяется**. В «Как это посчитано» обе строки показаны раздельно.

Пример (A): рождение 11:00:00 UTC, ли-чунь 15:18:44 UTC → рождение **до** термина → год 1983 (癸亥), месяц 丑. По альтернативной практике сравнивались бы 13:44 (TST Волгограда) и 23:19 (Пекин) — в этом случае результат тот же, но при рождении в Волгограде между 15:19 и 20:19 UTC ответы разошлись бы.

### 5.4 Столп дня: 60-дневный цикл и смена дня в 23:00 (T-5)

**ID** `bz.pillar.day` · **версия** 0.1.0 · **источник:** непрерывный счёт дней; опорная константа проверена по `lunar-python`; смена дня — **решение D-106** (школы расколоты, `skeletons.md` §3.3).

```
JDN(Y, M, D) — номер юлианского дня григорианской даты (на полдень), алгоритм Флигеля — Ван Фландерна:
   a = (14 − M) div 12;  y = Y + 4800 − a;  m = M + 12·a − 3
   JDN = D + (153·m + 2) div 5 + 365·y + y div 4 − y div 100 + y div 400 − 32045

номер_дня = ( JDN + 49 ) mod 60          0 = 甲子        ← опорная константа 49
ствол = ( JDN + 9 ) mod 10;  ветвь = ( JDN + 1 ) mod 12
```

Какая дата подставляется:

```
дата_TST, время_TST — по §2.8
если время_TST ≥ 23:00:00  →  дата столпа = дата_TST + 1 сутки      # поздний час Крысы уходит следующему дню
иначе                        →  дата столпа = дата_TST
```

Деления на «ранний и поздний час Крысы» (早子时 / 晚子时) нет: вся стража 23:00–01:00 принадлежит новому дню, и ствол часа считается от ствола **нового** дня. Альтернатива (смена в полночь) хранится в профиле только для сверки с калькуляторами.

| Пример | Дата и время TST | Дата столпа | JDN | Номер | Столп дня |
|---|---|---|---|---|---|
| Самопроверка константы | — | 01.01.2000 | 2 451 545 | 54 | **戊午** |
| A | 04.02.1984 13:44 | 04.02.1984 | 2 445 735 | 4 | **戊辰** |
| B | 15.06.1987 10:30 | 15.06.1987 | 2 446 962 | 31 | **乙未** |
| C | 22.12.1990 22:53 | 22.12.1990 (до 23:00 — день не меняется) | 2 448 248 | 57 | **辛酉** |
| E | **14**.06.1987 23:20 | **15**.06.1987 (после 23:00) | 2 446 962 | 31 | **乙未**; при смене в полночь было бы 甲午 |

Карта E показывает оба эффекта разом: по часам роддома — 15 июня 00:50, по истинному солнечному времени — ещё 14 июня 23:20, по правилу 23:00 — столп уже 15 июня. **Golden:** `GB-03`, `GB-04`.

### 5.10 Да-юнь (T-6)

```

        обратное — от ПРЕДЫДУЩЕГО цзе до рождения
возраст_входа:  3 суток = 1 год,  1 сутки = 4 месяца,  1 стража (2 ч) = 10 дней
        лет = floor(Δ / 3);  r = Δ − 3·лет;  месяцев = floor(4·r);  дней = floor( (4·r − месяцев) · 30 )
дата_входа = дата рождения + лет + месяцев + дней (календарное сложение)
столп k-го десятилетия (k = 1…9) = столп месяца ± k шагов по 60-ричному циклу (+ прямое, − обратное)
каждое десятилетие длится 10 календарных лет от даты_входа
```

Отображение: только год (`thesis-catalog.md` §4), возраст — `round(Δ / 3)` до целого, с подписью «около». Расхождение на ± 1 год с калькуляторами из-за округления — ожидаемый класс, не ошибка (`ARCHITECTURE.md` §6.3).

### 5.11 Сила господина дня: три сигнала (M-4)

**ID** `bz.dm.season`, `bz.dm.roots`, `bz.dm.support` · **версия** 0.1.0 · **«правило Луноры по трём классическим признакам»**. Три признака названы в традиции (Ди Тянь Суй, Цзы Пин Чжэнь Цюань); числовых порогов в текстах нет — все бинаризации ниже **авторские**. Одного числа «сила» движок **не выдаёт**.

**Сигнал 1 — сезон (得令).** Отношение стихии главного ци ветви месяца к стихии господина дня. Пятиступенчатая шкала 旺相休囚死 — из традиции (Сань Мин Тун Хуэй `[сверить]`):

| `r = (стихия месяца − стихия господина) mod 5` | Состояние господина | `season_support` |
|---|---|---|
| 0 — та же стихия | 旺 процветает | **да** |
| 4 — месяц порождает господина | 相 поддержан | **да** |
| 1 — господин порождает месяц | 休 отдыхает | нет |
| 2 — господин контролирует месяц | 囚 заперт | нет |
| 3 — месяц контролирует господина | 死 мёртв | нет |

**Сигнал 2 — корни (通根, 得地).** Корень — скрытый ствол **той же стихии**, что господин дня (любой полярности), в любой из четырёх ветвей. Сигнал — список `(столп, уровень: главный / средний / остаточный)`.

`roots_support = да ⇔ есть корень уровня «главный»  ИЛИ  корней любого уровня ≥ 2`

**Сигнал 3 — опора (得势).** Среди трёх остальных **проявленных** стволов (год, месяц, час) считаются стволы той же стихии (r = 0) и стихии ресурса (r = 4).

`support = да ⇔ таких стволов ≥ 2`

**Семейства доктрин — определение к Р-1 (канон; ссылаться сюда из `consensus-map.md`, `agreement-rules.md`, `data-model.md`).** У каждого условия голоса есть `family_id`; согласие засчитывается **только между разными семействами**. Семейства — по доктринальной линии, а не по кадру:

| `family_id` | Школы | Почему вместе |
|---|---|---|
| `planetary` | **western + vedic** | общая эллинистическо-индийская доктрина достоинств планет (обитель, экзальтация, изгнание, падение); ведические достоинства грах — той же линии, поэтому их совпадение с западными **не независимо** (в общем кадре — 100 %) |
| `chinese` | **bazi** | 干支/五行 — китайская календарная доктрина, отдельная линия |
| `numerological` | **numerology** | буквенно-числовой метод и психоматрица, отдельная линия |

**Следствие:** независимых семейств — **максимум три**. «Western и vedic согласны» — это согласие **внутри одного семейства** `planetary`, в доказательство консенсуса оно не идёт.

🔑 **Где живёт метка (сведено с `API-КОНТРАКТ.md`).** `family_id` / `doctrine_family` — **детерминированная функция `system_id`** (одна школа всегда в одном семействе: western,vedic→`planetary`; bazi→`chinese`; numerology→`numerological`). Поэтому она одновременно: (а) едет в `Signal` как поле `doctrine_family` (API §2.2) — как свойство школы-источника; (б) используется при агрегации консенсуса — согласие считает **различные семейства** среди подтверждающих тезисов. Отдельной таблицы «метка на условии» не нужно: условие тезиса опирается на сигналы одной школы и наследует её `family_id`. Расхождения между API (на сигнале) и движком (при подсчёте) нет — источник один.

**Три методических риска держать под контролем:** (1) тождество школ (общий кадр/доктрина делают «согласие» иллюзией) — закрыто Р-1; (2) перекос порогов (голос становится шумом или молчит) — закрыто Р-3/Р-7/йоги; (3) авторские числа под видом традиции — все названы «правило Луноны».

**Остаётся живому практику:** веса/пороги силы Ба-Цзы; построчная сверка термов с Лилли; выписка 120 ячеек тяо-хоу; определения йог и отмены Кемадрумы; правило квадрата для дат с 2000 (текст Александрова); допустимость ранжирования имён.
