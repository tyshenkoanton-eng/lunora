# G14 — Аналитика и критерии успеха

**Статус гейта:** `accepted` (решения приняты; инструмент и пороги — на замер первой когортой).
**Вход:** G3 (ICP, момент ценности), G4 (first value = профиль «6 шкал», возврат без пуша), G5 (экономика, конверсия R-06).

---

## 1. Момент активации и ключевые метрики
- **Активация (first value):** новый пользователь **дошёл до профиля «6 шкал с консенсусом»**. Метрика: % новых, достигших профиля.
- **Возврат (retention):** вернулся **на следующий день к утреннему прогнозу без пуша** (G4). Метрики: D1/D7 retention.
- **Монетизация:** конверсия в первую покупку (R-06, цель-ориентир 2,5–3%), ARPPU (R-31 — критично непроверено).

## 2. Воронка
`старт бота → онбординг (данные рождения + согласие) → профиль (АКТИВАЦИЯ) → полный разбор → пейволл → покупка → повтор`
На каждом стыке — drop-off; главные точки внимания: онбординг (барьер «время рождения», R-?), пейволл.

## 3. Guardrail-метрики (не дать «улучшить» ценой вреда)
- **Стоимость LLM на пользователя** ≤ бюджет (R-05): алерт при превышении.
- **Доля возвратов/отказов оплаты** (Stars): рост = проблема доверия/бага.
- **Латентность разбора** (сборка карты + LLM-синтез).

## 4. Kill-criteria [РЕШЕНИЕ, числовые — проверяются на первой когорте]
- Активация < **40%** новых → онбординг/ценность не работают.
- D7 retention < **15%** → нет привычки возврата.
- Конверсия в покупку < **2,0%** после первых **~200** плательщико-возможных → экономика не сходится (R-06).
- Стоимость LLM/пользователь устойчиво > бюджета и не чинится архитектурой (R-05) → модель нежизнеспособна.
Любой сработавший kill → REVISE бизнес-модели, не «докрутка маркетинга».

## 5. Словарь ключевых событий (event dictionary)
| Событие | Триггер | Свойства |
|---|---|---|
| `onboarding_started` | открыл ввод данных рождения | source |
| `birth_data_submitted` | ввёл дату/время/место | has_time (bool) |
| `profile_viewed` *(активация)* | открыл 6 шкал | consensus_shown |
| `full_report_opened` | открыл полный разбор | — |
| `paywall_viewed` | увидел экран оплаты | product (dialog/слот/мы-с-ним) |
| `purchase_succeeded` | оплата прошла (Stars/ЮKassa) | product, amount, method |
| `morning_forecast_returned` | вернулся к утреннему прогнозу | day_n |
Свойства — **без ПДн** (не слать дату рождения/ФИО в аналитику).

## 6. Инструмент [РЕШЕНИЕ]
Приватность-first (152-ФЗ, R-39): **без отправки ПДн зарубежному аналитик-провайдеру**. Вариант — self-hosted (напр. простое событийное логирование на своём сервере / российский провайдер). Выбор конкретного инструмента — на старте реализации; контракт событий (п.5) от инструмента не зависит.

## Самоотчёт (выход G14)
- Exit: success/guardrail метрики измеримы `verified` · словарь событий задан `verified` · kill-criteria числовые `verified` · privacy учтён `verified` · конкретный инструмент — `conditional` (выбор при реализации, контракт событий фиксирован).
