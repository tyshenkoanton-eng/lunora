## 1. Метод

### 1.1 Что проверяется автоматически при каждой сборке

| Проверка | Зачем |
|---|---|
| Связность: каждая ссылка ведёт в существующий экран | 55 переходов, вручную не удержать |
| Баланс `<div>` | ⚠️ regex-правки съедают закрывающие теги |
| Синтаксис JS | Одна опечатка гасит весь прототип |
| Парность обратных кавычек | Экраны — шаблонные строки |
| Дубли функций и переменных | ⚠️ поймано 6 случаев, см. §6 |
| Дубли обработчиков на один селектор | Два обработчика отменяют друг друга |

🔑 **Ведёт ли ссылка в *правильный* экран — проверяется только вручную.** Такие ошибки были и будут: за сессию их поймал стейкхолдер трижды.

### 1.2 Данные вместо разметки

Однотипные экраны — не копии, а генераторы из таблиц:

| Таблица | Что порождает |
|---|---|
| `PROD` — 8 продуктов | 6 экранов конвейера покупки |
| `NCELL` — 9 клеток квадрата | 9 экранов разбора клетки |
| `NLINE` — 8 линий | 8 экранов линии |
| `THEME` — 5 тем | 5 экранов темы |
| `HELP` — 4 категории | 4 экрана справки |
| `LEGAL` — 4 документа | 4 экрана документа |
| `PEOPLE` — 3 человека | экран удаления по каждому |

🔑 **Девятый продукт стоит шести строк данных и ни одного нового экрана.**

## 4. Продуктовый конвейер

```
8 продуктов → Витрина → Данные → Глубина → Оплата → Сборка → Документ → 8 документов
                                      ↑                 ↓
                              условия до сделки    списание при выдаче
```

**Различие продуктов живёт в конфигурации:** набор полей, глубина расчёта, шаги сборки, структура документа. Экраны общие.

🔑 **Момент списания совпадает с моментом оказания услуги физически** — холд ставится до расчёта, списание при выдаче. Это видно в логах платёжного провайдера и сильнее любой формулировки в оферте.

### 4.1 Структура восьми документов

У каждого своя, а не общая заглушка. Разделы и порядок зафиксированы, тексты не написаны.

| Документ | Своя конструкция |
|---|---|
| Совместимость | Два коротких портрета · «из-за чего повторяются ссоры» главным разделом · счёт по школам |
| Мой ребёнок | Родительский слой отдельным блоком · «где вы расходитесь» |
| Выбор имени | Таблица вариантов по трём числам · топ-3 · раздел «чего этот разбор не делает» |
| Смена фамилии | Было/стало · **отдельно «что остаётся при вас»** |
| Карта на год | Шкала четырёх периодов · часть большого цикла · четыре сферы |
| Дата, ветка А | Лучший день · три альтернативы · что пропустить |
| Дата, ветка Б | Выбирать нечего — состояние и подготовка |
| PDF карты | Своей структуры нет: продаётся форма, не текст |

## 5. Состояния экранов

### 5.1 Пять режимов, применимых к любому экрану

Переключатель в панели прототипа. Работает на всех 109 экранах, включая будущие.

| Состояние | Как выглядит | Где возможно |
|---|---|---|
| Норма | экран как есть | везде |
| Загрузка | **скелетон по форме экрана**, не спиннер | везде |
| Пусто | знак, фраза, одно действие | **только 5 экранов** |
| Ошибка | что случилось, что делать, куда уйти | везде, **4 разных текста** |
| Офлайн | полоса сверху, экран читаем | везде |

🔑 **Скелетон вместо спиннера.** Скелетон повторяет форму того, что грузится, — человек видит, чего ждать.

🔑 **Пустое состояние есть не везде.** Профиль, темы и школы строятся из карты, посчитанной при регистрации. Пустыми могут быть только списки.

🔑 **У ошибки четыре текста** — банк, наш расчёт, текст раздела, сервер. От того, чей сбой, зависит поведение человека дальше.

### 5.2 Три ситуации вне схемы

| | Почему отдельно |
|---|---|
| Платёж прошёл, подтверждение не дошло | Худший сценарий ниши. Экран не должен выглядеть ошибкой |
| Двойная оплата | Возврат **до обращения**, не по жалобе |
| Данные посчитались не все | Не сбой, а обычный режим: времени рождения нет у большинства |

## 6. ⚠️ Шесть коллизий в одном файле

Прототип — 300 КБ с плоским пространством имён. За сессию поймано:

| Что | Симптом |
|---|---|
| `.w-btn` без базового стиля | 20 кнопок рисовались текстом |
| `.w-label` без базового стиля | Метка выглядела как значение |
| `.navarr i` вместо `.navarr > i` | Точки-индикаторы стали кнопками 48 px |
| `.mem.edit` попал под старое `.edit` | Блок правки зеркалился целиком |
| `memCheck` и `TZ` объявлены дважды | Второе перекрывало первое, `TZ` — после использования |
| 5 блоков обработчиков вставлены дважды | Раскрытие срабатывало дважды и отменяло себя |

🔑 **Все шесть — следствие плоских CSS-классов и правки по текстовому маркеру.** В React с модульными стилями этот класс ошибок не воспроизводится. Прототип на выброс; переносится логика, а не код.
