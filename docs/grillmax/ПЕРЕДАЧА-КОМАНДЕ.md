# Лунора — пакет для передачи команде разработки

**Назначение:** войти в проект без прежнего контекста и начать разработку без белых пятен. Это **точка входа** — читать первым.
**Дата сборки:** 2026-11-17 · **Статус:** передаётся для реализации; незакрытые решения перечислены явно (раздел 6).

---

## 1. Что это и где границы

**Лунора** — Telegram Mini App (далее MAX, веб, мобильные): персональный разбор личности по 4 системам (западная и ведическая астрология, Ба-Цзы, нумерология), сведённым в один разбор. Позиционирование — инструмент самопознания на данных о рождении, **не эзотерика, не гадание, не медицина, не прогноз событий**.

**Границы v1 (что входит):** онбординг → расчёт карты → бесплатный профиль (темы) → платные разборы (год, ребёнок, совместимость, дата) → чат пакетами вопросов → утренняя лента → настройки/удаление.
**Отложено из v1:** продукты по подбору/смене имени (нет правила ранжирования); связывание аккаунтов Telegram↔MAX; зарубежный LLM до процедуры РКН (стартуем на OpenRouter с процедурой).

**Ключевые принципы (не нарушать при реализации):**
- Расчёт отделён от интерпретации; **LLM не считает астрологию и не выдумывает факты**; бесплатный слой — без LLM (замороженная библиотека).
- «Согласие школ» — **повод присмотреться, не доказательство** (школы не независимы, считаются от одной астрономии; согласие засчитывается только между разными семействами доктрин).
- Авторские числовые правила называются **«правило Луноры»**, а не «метод школы».
- Fail closed: невычислимая по правилу величина — школа молчит, а не «считает примерно».

## 5. Пять сценариев контрольной передачи (критерий готовности)

Разработчик без прежнего контекста должен по пакету описать **единственную** последовательность состояний для каждого. Контракты — в `TRANSACTIONS-КОНТРАКТЫ.md`.
1. Оплата подтверждена, процесс падает до постановки задачи. → §2 Outbox.
2. На балансе 1 вопрос, два устройства шлют разные сообщения. → §5 Резерв квоты.
3. Данные изменены, старый worker ещё строит документ. → §10 Пересчёт (CAS).
4. Аккаунт удалён во время извлечения памяти, затем восстановлена старая копия БД. → §7 Удаление + §8 ключи/бэкапы.
5. Платный пользователь теряет доступ к Telegram и должен получить купленный результат. → §7 API (DeliveryPort), B1/**D-121** (оплата по площадке: Stars внутри Telegram, ЮKassa на MAX/вебе; D-116 отменён).

## 6. Что ещё НЕ закрыто (явно, до/в начале разработки)

**Решения приняты, значения уточнить при реализации:** численные пороги (ретраи, backoff, TTL резерва, срок сверки, срок ссылок); частичный возврат — детали; spike ЮKassa (подлинность вебхука, возврат по СБП/из кабинета); идемпотентность чеков НПД. **Хранение `USER_KEY` — уже решено:** вариант А (вне дампа, `N_k = 14 дней`, `TRANSACTIONS-КОНТРАКТЫ.md` §8.1, B7), выбирать не нужно.

**Контент (главный объём работы):** библиотека ~2 800 блоков почти пуста; расчётные таблицы (достоинства Лилли построчно, термы, 120 ячеек тяо-хоу) — выписать человеком по первоисточнику; старт — «срез 1» на 1–2 темах.

**Специалисты к запуску:** юрист (согласие/оферта/РКН/словарь — `legal/ПРАВОВЫЕ-ТЕКСТЫ.md` §«требует юриста»); практик-астролог (подтвердить «правила Луноры» — `ENGINE-SPEC §8.4`, `ИССЛЕДОВАНИЕ-МЕТОД`).

**Внешние действия (оператор):** уведомление РКН по ст. 22 до первого сбора данных; процедура ст. 12 по OpenRouter (3–6 недель, самый длинный путь — первым); регистрация самозанятости; товарный знак (A-20, 12–18 мес).

**Методические хвосты:** пересчёт примеров `consensus-map §5` и golden-значений под новые правила §8.4.

## 7. Известные ограничения пакета
- Прототип — wireframe, демо-данные (реквизиты чека замаскировать перед внешней передачей).
- Ссылки на `spec/` и латинские имена в этом пакете **верны** (не переименовывать при распаковке). ⚠️ **Исключение:** ссылки на `research/…` ведут на рабочие материалы оператора, которые **намеренно не входят в пакет** (копирайт, см. `ENGINE-SOURCES.md`) — они не разрешаются и это ожидаемо. Проверка связности — `tools/check-consistency.py`: **блокирующих замечаний нет, код выхода 0** (битых внутренних ссылок, casefold-коллизий, снятых терминов в UI и неоговорённой «маржи >85 %» — нет). Ссылки на `research/…` и архивные ID рисков (R-24…R-38, R-51 из глав Discovery) выводятся как **информационные** и на код выхода не влияют. Гейт проверяет, что корень существует и это пакет «Лунора» (ложный «зелёный» на неверном пути исключён, код 2). Рядом — `tools/check-decision-propagation.py` (решение D-121 разнесено по всем каноническим файлам, отменённый D-116 не числится действующим) и `tools/gen-screen-codes-live.py` (каталог экранов из **живого** реестра прототипа, 310 экранов; требует node+playwright).
- Исследование метода проверено **симуляцией 12 000 карт** (не «реальными картами»); скрипты не входят — воспроизводимость через golden-кейсы при реализации.
