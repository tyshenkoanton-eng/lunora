# ADR-003 — Фронтенд строго token-driven и компонентный

**Дата:** 2026-11-20 · **Статус:** принято · **Гейт:** G11 (следствие решения G9)

## Контекст
Полный визуальный дизайн 141 экрана — это ~полгода, и он не готов (финальный облик дорабатывается параллельно). При этом бизнес хочет **начать техническую реализацию параллельно с дизайном**. Это возможно только если смена/доводка визуала потом дёшева.

## Решение
Фронтенд реализуется **только** так:
1. **Токены** (`tokens.json`, 3 яруса примитив→семантика→компонент) — единственный источник цветов, отступов, типографики, радиусов. Тема (светлая/тёмная) — перемаппинг семантического яруса.
2. **Компоненты** — экраны собираются из переиспользуемых компонентов (инвентарь G9, ~20 штук) со состояниями, привязанными к токенам.
3. **Запрет хардкода:** ни одного зашитого цвета/пикселя/шрифта в разметке экранов. Любое стилевое значение — ссылка на токен.

## Последствия
- **Смена облика = правка `tokens.json` + стилей ~20 компонентов.** Все 141 экран обновляются сами. Дни, не месяцы.
- Реализация стартует на **временном скине** (черновые токены Мятной); финальный облик (включая шрифт Lunera и доводку оттенков) впрыгивается позже без переделки экранов.
- Дизайн и разработка идут **параллельно**: контракт между ними — `tokens.json` + инвентарь компонентов.
- Цена: дисциплина на старте (настроить токен-слой и библиотеку компонентов до экранов). Это окупается первым же изменением дизайна.

## Проверка (exit)
- Код-ревью отклоняет любой захардкоженный стиль.
- Смена одного семантического токена видимо меняет все зависимые экраны (smoke-тест темизации).
- Переключение светлая/тёмная работает без правок разметки.
