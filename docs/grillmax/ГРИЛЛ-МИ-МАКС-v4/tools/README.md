# Инструменты ГРИЛЛ МИ МАКС

## `check-consistency.py` — референс-чекер связности и распространения решений

Машинная половина предохранителя **П3** (смысловую проверку по существу агент делает сам — см. SKILL.md). Портативный: специфику проекта читает из конфига, а не хардкодит. Только чтение.

```bash
python3 tools/check-consistency.py [корень_пакета]
```
По умолчанию корень — родитель `tools/`. Коды выхода: `0` нет блокирующих · `1` есть блокирующие · `2` корень не похож на пакет.

### Что проверяет (машинно)
1. **Битые внутренние markdown-ссылки** — блокирующе; ссылки за пределы пакета — информационно.
2. **Casefold-коллизии** имён файлов (`ENGINE.md` vs `engine.md`) — блокирующе.
3. **Распространение решений** из `_SESSION.json` (`gates[*].decisions[]`) и/или `DECISIONS.md`:
   - активное решение должно быть упомянуто во всех своих `dependents` — иначе `decision-not-propagated` (блок);
   - отменённое (`superseded`) не должно встречаться как действующее (без слов «отменён/заменён/устар» рядом) — иначе `cancelled-referenced` (блок).
4. **Запретные термины** — только если заданы в конфиге (см. ниже).
5. **ID рисков** без определения в `RISKS.md` — информационно.

### Конфиг (необязательный): `tools/grillmax-check.config.json`
```json
{
  "banned_terms": ["старый бренд", "устаревш\\w* модель оплаты"],
  "banned_scope_globs": ["**/*.html", "wireframes/**/*.html"]
}
```
- `banned_terms` — регулярки снятых терминов, которых не должно быть в видимом тексте (напр. после смены модели оплаты/бренда). Нет конфига — проверка пропускается.
- `banned_scope_globs` — где искать (по умолчанию `**/*.html`), чтобы не ловить сам термин в методическом описании.

### Реестр решений
Чекер читает решения из `_SESSION.json` (поля `id`, `status: active|superseded`, `dependents: [файлы]`, `superseded_by`) и/или из таблицы `DECISIONS.md`:
```
| ID | Значение | Источник | Зависимые | Версия | Статус |
|----|----------|----------|-----------|--------|--------|
| D-001 | Stars внутри Telegram | G5 | 11_architecture.md, 16_roadmap.md | rev-2 | active |
```

### Важно
Машина ловит **форму** (ссылки, имена, присутствие ID, запретные строки). **Смысл** (одно бизнес-правило не противоречит другому, даже если числа совпали) проверяет агент и фиксирует вердикт — это требование exit П3. Чекер не заменяет внешнее ревью, но ловит класс «хвостов после правки» за секунды.

> Пример проектной настройки (с якорями и терминами конкретного продукта) — в рабочем проекте, не в методологическом пакете.
