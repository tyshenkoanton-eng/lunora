# ГРИЛЛ МИ МАКС — бандл из 4 равноправных скиллов

Это **4 отдельных скилла**, не вложенных друг в друга. Каждый — свой пакет со `SKILL.md`, устанавливается независимо (папка в `.claude/skills/` или `.agents/skills/`).

```
ГРИЛЛ-МИ-МАКС-v4/
├── grill-mi-max/      — оркестратор: 16 гейтов L0 Discovery + согласованность (+ tools/, changelog)
├── brand-identity/    — бренд: знак, цвет, шрифт, voice, brand.tokens.json
├── visual-concept/    — UI-система: токены, компоненты, контраст, тёмная тема
└── prototype/         — прототип: лестница фиделити (функции→потоки→вайрфреймы→лоу-фай→хай-фай)
```

## Как они работают вместе (ручной хендофф)

GRILL MI MAX **не вызывает другие скилли сам**. Он доходит до момента, где нужен другой тип работы, и передаёт эстафету через файлы:

```
1. GRILL MI MAX доходит до craft-гейта (бренд G6 / прототип G8,G10 / визуал G9)
   → ставит гейт на ПАУЗУ и готовит файл-бриф <гейт>.brief.md (контекст + задача + exit).
2. Ты запускаешь нужный отдельный скилл. Он первым делом спрашивает:
   «Есть ли бриф из GRILL MI MAX?» → берёт его и работает (или автономно).
3. Скилл отдаёт артефакт + самоотчёт и говорит: «верни это в GRILL MI MAX».
4. Ты возвращаешься в GRILL MI MAX, отдаёшь артефакт. Он валидирует против exit,
   ставит статус и добавляет в общий отчёт (00_SUMMARY). Гейт снимается с паузы.
```

Каждый craft-скилл **самоценен** и запускается отдельно (напр. `visual-concept` соберёт дизайн-систему существующему продукту без всех гейтов). GRILL MI MAX держит **сквозную согласованность**: без него артефакты есть, но никто не сшивает их в один проект.

Если переключаться не хочешь — GRILL MI MAX может сделать работу craft-гейта **сам**, по тому же брифу и exit.

## Контракт между скиллами
- **Бриф** (`<гейт>.brief.md`) — что GRILL MI MAX передаёт наружу: вход + задача + exit + трассируемость.
- **Артефакт + самоотчёт** — что скилл возвращает: результат + по каждому exit-критерию статус (`verified`/`specified_only`/`conditional`/`waived`) + провенанс (из каких гейтов, версии входов).
- GRILL MI MAX при импорте **валидирует** (не на слово) и фиксирует устаревание (`stale`) при изменении входов.

Граница дисциплин: **бренд (G6) создаёт знак → UI-система (G9) потребляет его → прототип (G10) показывает.**

## Установка
Скопируй нужные папки в `.claude/skills/` или `.agents/skills/`. ⚠️ Имя `prototype` может быть занято другим скиллом окружения — тогда переименуй папку и `name:` во фронтматтере (напр. `gm-prototype`).

## Универсальность
Скилли **не привязаны к проекту**: специфику (термины, реестр решений) задаёшь данными. Опциональный чекер `grill-mi-max/tools/check-consistency.py` читает конфиг `grillmax-check.config.json`, ничего не хардкодит.
