# Prototype — лестница фиделити с ручной приёмкой

Продуктовый принцип: **детализация растёт ступенями, и на каждую следующую поднимаемся только когда предыдущая принята человеком.** Прыжок через ступень — это полировка пикселей на непроверенной структуре, то есть выброшенная работа. Прототип на каждой ступени отвечает на **один продуктовый вопрос** и останавливается.

---

## Старт: есть ли бриф из GRILL MI MAX?
**Первый вопрос пользователю:** «Есть ли у тебя бриф из GRILL MI MAX (файл `08_proto_lo.brief.md` или `10_proto_hi.brief.md`) — список функций, user stories/flows, а для хай-фай ещё UI-язык G9 и знак G6?»
- **Есть** → возьми его как вход, иди по лестнице от текущей ступени, в конце верни артефакт в GRILL MI MAX.
- **Нет (для hi)** → останови: «Для хай-фай нужен принятый лоу-фай и UI-язык G9». Автономно (lo) — собери структуру/сценарии сам.

## Лестница (продуктовый подход)

| № | Ступень | Артефакт | Продуктовый вопрос ступени | Чекпоинт (принимает человек) |
|---|---|---|---|---|
| 0 | **Список функций** | инвентарь возможностей / scope | что продукт вообще должен уметь? | список функций согласован, лишнее отрезано |
| 1 | **Истории + потоки** | user stories + user flows | что получает пользователь (story) и каким путём (flow)? | каждая история покрыта потоком, критические пути полны |
| 2 | **Блок-схемы потоков** | по каждому flow — схема экранов/решений/состояний | логика путей сходится, ветви и ошибки учтены? | схемы без тупиков и дыр, состояния на месте |
| 3 | **Вайрфреймы (лоу-фай)** | серые макеты структуры, без цвета | понятна ли структура экранов и иерархия? | расположение и приоритеты блоков приняты |
| 4 | **Кликабельный лоу-фай** | навигируемый серый прототип + **тест с людьми** | проходят ли люди путь без подсказок? | ≥1 представитель ЦА прошёл сценарий; находки записаны |
| 5 | **Хай-фай** | применён визуальный язык, эталонные экраны + приёмка | работает ли как цельный визуальный опыт, читается ли копия? | приёмка визуала стейкхолдером |

**Границы владения.** Ступени **0–1** — это продуктовая структура: в GRILL MI MAX они делаются в контуре A (объём) и гейте **G7** (UX-структура) и приходят сюда брифом. Этот скилл владеет **ступенями 2–4** на `fidelity=lo` (гейт **G8**) и **ступенью 5** на `fidelity=hi` (гейт **G10**). Автономно — скилл может пройти лестницу целиком, но ступени 0–1 всё равно делаются первыми и принимаются.

---

## Главное правило: прототип — не продукт (потолок П1)

Прототип — **чёрная дыра**: впитывает экраны, кейсы и копирайт бесконечно (провал v3: 310 экранов, 12 кругов ревью). Защита — сама лестница + правила:

- **Ступень соответствует вопросу.** Лоу-фай серый by design (не красить). Хай-фай доводит до эталона **ключевые** экраны (first value + 1–2 целевых), не все.
- **Покрываем Must-flows**, а не всё. Экран вне ключевого сценария — не в этой фазе.
- **Итерируешь без новых решений — ступень пройдена.** Полировка пикселей и всех строк — это L1+, не L0.
- Прототип — **источник вида и копирайта** для разработки, но **не контракт поведения**: переходы, состояния, машины состояний живут в контрактных гейтах (G11+); прототип им не перечит, но и не заменяет.

Если тянет «ещё чуть-чуть допилю» — ступень уже пройдена. Верни артефакт на приёмку.

---

## Правило ручной приёмки (чекпоинт между ступенями)

Это ядро подхода. На каждой ступени: **показать артефакт → человек (PM/стейкхолдер) принимает или возвращает → только после приёмки поднимаемся выше.** Нельзя подниматься «на свой страх»: не принята структура (ступень 3) — не рисуем вайрфреймы в хай-фай. Возврат на ступени ниже дешевле возврата сверху.

Для каждой ступени фиксируй: что показано, вердикт (принято / доработать), что исправить. Это и есть продуктовая трассируемость «почему прототип такой».

## Бриф (вход)

Из GRILL MI MAX приходит файл-бриф `<гейт>.brief.md` (формат — в SKILL.md, «Craft-скиллы и импорт по контракту»); автономно — собери тот же контекст сам.

**Общее:** объём/список функций (ступень 0), user stories и user flows (ступень 1, из G7), ключевой сценарий first value (G4), ICP (G3), список Must-flows.

**Для `fidelity=lo` (G8):** фиделити серая, визуального языка ещё нет — не раскрашивать. Владеешь ступенями 2–4.
**Для `fidelity=hi` (G10):** принятый кликабельный лоу-фай (ступень 4) + **дизайн-язык из G9** (токены, компоненты) + знак из G6 + финальные тексты ключевых экранов. Владеешь ступенью 5.

Нет user flows, а просят лоу-фай → верни: «G7 не закрыт, строить не на чем». Нет дизайн-языка, а просят hi → верни: «G9 не закрыт». Чего-то в брифе нет — запроси, не выдумывай.

## Процесс

### fidelity=lo (G8) — ступени 2–4, каждая с приёмкой

**Ступень 2 — блок-схемы потоков.** По каждому Must-flow собери схему: экраны → решения/развилки → состояния (empty/loading/success/error/offline/recovery). Приём каждого отдельного состояния как узла, а не «на потом». → Приёмка: логика сходится, тупиков нет.

**Ступень 3 — вайрфреймы (лоу-фай).** Серые макеты ключевых экранов: расположение блоков, иерархия, навигация. Без цвета, без картинок, без финальной копии (плейсхолдеры по смыслу). **Полнота решений ≠ полнота отрисовки:** собери матрицу «экран × применимые состояния», но рисуй отдельным вайрфреймом только **уникальную структуру и критичные переходы**; типовые состояния (loading/empty/error) — через переиспользуемый образец + ссылку на правило. → Приёмка: структура и приоритеты приняты.

**Ступень 4 — кликабельный лоу-фай + тест структуры.** Свяжи вайрфреймы в навигируемый серый прототип Must-flows (онбординг → first value → core loop → оплата/ошибки). Затем **UX-тест:** дай ≥1 представителю ЦА конкретные задания, наблюдай где застревают. Нет тестеров → документированный solo-прогон с позиции новичка + список проблемных мест (честный fallback, пометь). → Приёмка: сценарий проходится без подсказок; структурные проблемы ушли назад в G7.

Верни: прототип + блок-схемы + вайрфреймы + протокол теста + вердикты приёмки по ступеням.

### fidelity=hi (G10) — ступень 5

1. Примени дизайн-язык G9 (токены, компоненты, типографика, тёмная/светлая) и знак G6 к принятой структуре из ступени 4.
2. Доведи **ключевые** экраны (first value + 1–2 целевых/платных) до эталона с **настоящим текстом** (не lorem).
3. Отрисуй пустые/error/loading визуально.
4. → Приёмка визуала стейкхолдером.

Верни: хай-фай прототип + эталонный раздел + вердикт приёмки.

## Exit-критерии (их проверяет GRILL MI MAX)

**G8 (lo):**
- [ ] Блок-схемы по всем Must-flows (экраны/решения/состояния), приняты
- [ ] Вайрфреймы ключевых экранов со всеми состояниями, структура принята
- [ ] Кликабельный лоу-фай покрывает ключевой сценарий (first value) и Must-flows
- [ ] ≥1 представитель аудитории прошёл без подсказок (или честный solo-fallback с находками)
- [ ] Результаты теста задокументированы, структурные проблемы ушли в G7
- [ ] Вердикты ручной приёмки зафиксированы по каждой ступени
- [ ] Не раскрашен, не переусложнён (потолок соблюдён)

**G10 (hi):**
- [ ] Ключевые Must-экраны в хай-фай с применённым языком G9 и знаком G6
- [ ] Эталонный раздел с настоящим текстом (не lorem)
- [ ] Пустые/error/loading отрисованы визуально
- [ ] Приёмка визуала стейкхолдером
- [ ] Доведены ключевые экраны, а не все (потолок соблюдён)
- [ ] Зафиксировано: прототип — источник вида/копирайта, не контракт поведения

## Возврат в GRILL MI MAX
Когда прототип готов — скажи пользователю: «Готово. Вот артефакт (прототип + блок-схемы/вайрфреймы или эталонные экраны) и самоотчёт с вердиктами приёмки по ступеням. Верни их в GRILL MI MAX — он проверит против exit гейта (G8 или G10) и добавит в отчёт. Пометь честно: тест был с людьми (`verified`) или solo-прогон (`conditional`).» Автономный запуск — артефакт самоценен.

## Если доступен исполнительский крафт

На хай-фай (ступень 5) доводку ключевых экранов до эталона можно делегировать исполнительским скиллам, если они есть (напр. `impeccable`, `apple-design`, а для перебора визуальных направлений одного элемента — скилл построения UI-вариантов). Дай им на вход **принятую структуру (ступень 4), язык G9 и знак G6** — они исполняют принятую систему, не придумывают новую. Потолок П1 и ручная приёмка остаются за этим скиллом. Нет таких скиллов → доводи сам по языку G9.

## Самоотчёт о соответствии (выход)

Верни артефакт **с самоотчётом**, чтобы GRILL MI MAX проверял не на слово:
- `produced_by: prototype`, фиделити (lo/hi), `brief: <гейт>.brief.md`, `inputs: [гейты]`, дата.
- Чек-лист: по каждому exit-критерию гейта — ✓/✗ + где в артефакте выполнено.
- **Лестница:** на какой ступени остановились, вердикт приёмки каждой пройденной ступени.
- Трассируемость: какие Must-flows из G7 покрыты (и какие сознательно нет); для hi — какие токены G9 / знак G6 применены.
- Честно: фиделити деградирована? тест был solo-fallback, а не с людьми? ступень не принята, но пошли выше? — пометь.

Самоотчёт — заявка исполнителя. Решает GRILL MI MAX при валидации; «сам сказал — не считается».

## Гигиена артефакта (если прототип — один HTML-файл)
- Держи **каталог экранов** генерируемым из реестра прототипа (а не вручную) — иначе каталог отстаёт от того, что реально рендерится.
- Автоматизируй проверки: нет мёртвых переходов, нет пустых экранов рендера, нет запретных терминов в видимом тексте (по правилам продукта).
- Помечай «принятые» экраны и сверяй их отпечаток, чтобы принятое не менялось молча при следующей правке.

## Если инструментов нет
Браузер недоступен → статические вайрфрейм-документы ключевых экранов + описание переходов таблицей (ступени 2–3 текстом/схемой). **Это не ослабляет exit автоматически:** пометь результат `specified_only` (структура описана, но не кликабельна), а UX-тест без людей — `conditional`. Передай GRILL MI MAX сигнал о деградации фиделити и невозможности живого UX-теста, чтобы соло-PM видел разницу между «проверено» и «описано».
