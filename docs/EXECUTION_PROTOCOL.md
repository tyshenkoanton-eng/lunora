# Протокол исполнения агентами — Лунора

Фиксированный документ. Как работа исполняется агентами: кто, в каком порядке,
с какой проверкой и на чьём решении.

Дисциплина слайса — в `LUNERA_STANDARDS.md` §3.1.
Форма задачи — в `TASK_CONTRACT.md`.
Хартия ревьюера — в `REVIEWER_CHARTER.md`.

---

## 1. Контур

```
  ОПЕРАТОР                          ← только решения: продукт, гейт, приёмка
      │
      ▼
  ОРКЕСТРАТОР (главная сессия)
  держит контекст · декомпозирует · распределяет · собирает
      │
      ├─ контракт задачи → РЕВЬЮ КОНТРАКТА → правка контракта → реализация
      │
      ▼
  ИСПОЛНИТЕЛЬ (изолированная ветка)      пишет по контракту, гоняет проверку
      │
      ▼
  РЕВЬЮ КОД (слепой) → КРИТИК РЕВЬЮ → расхождение? → ОПЕРАТОР
      │                                    │
      │ согласились                        └── возврат на доработку
      ▼
  ПРИЁМКА (зелёная проверка) → задача закрыта → гейт ждёт оператора
```

## 2. Роли

| Роль | Что видит | Что делает |
|---|---|---|
| **Оператор** | всё | продуктовые решения, утверждение разбивки, закрытие гейта |
| **Оркестратор** | контекст проекта, состояние | декомпозиция, распределение, сборка, эскалация |
| **Исполнитель** | контракт, свои файлы | реализация по контракту, зелёная проверка |
| **Ревьюер** | **только артефакт и контракт** | независимое ревью: корректность, риск, соответствие контракту |
| **Безопасник** | только дифф + чек-лист безопасности | отдельный проход: секреты, доступ, зависимости |
| **Критик ревью** | только ревью | «эта претензия — ложная?» |

**Слепой ревьюер — правило, а не пожелание.** Ревьюер не видит рассуждений
исполнителя. Иначе он оценивает не артефакт, а объяснение артефакта, и
подтверждающее предвкусие переносится через границу.

**Критик ревью — обязателен.** Если ревьюер и критик разошлись, вопрос идёт
оператору. Ревью не «прогоняется до зелёного любой ценой»: замечания
исполнителя может быть ложным, и это надо уметь отсечь, а не затащить в код.

## 3. Границы автономии

| Решение | Кто |
|---|---|
| Продуктовое: что делаем, для кого, как должно работать | **оператор** |
| Разбивка гейта на атомарные задачи | система предлагает → **оператор утверждает** |
| Закрытие **задачи** внутри гейта | система (по зелёной проверке) |
| Закрытие **гейта** | **оператор** |
| Релиз, публикация, внешние эффекты | **оператор** |

Система никогда не расширяет полномочия сама и не выносит продуктовых решений.
Её роль — готовить факты и варианты, а решение оставлять оператору.

## 4. Изоляция

- Каждая задача — **своя ветка или worktree**. Один писатель на файл.
- Параллельные задачи не делят рабочий каталог: файловые конфликты недопустимы,
  конфликт архитектуры — тем более.
- Изоляция файлов не равна изоляции окружения: порты, базы, внешние сервисы
  разводятся явно (свои `.env`, свои базы, свои диапазоны портов).

## 5. Экономия (правила, а не лозунги)

| Правило | Зачем |
|---|---|
| Шумное чтение — отдельной сессией, наружу только сводка | главный тред не тонет в мусоре |
| Одна итерация — одна свежая сессия | состояние на диске, а не в окне |
| Простая задача (проверка, классификация, поиск) — дешёвый исполнитель | рутина не должна стоить как архитектура |
| Контекст — только то, что нужно сейчас | «вычитка всего» дороже и хуже |
| Устаревший вывод инструментов — не переносить | он раздувает окно и сбивает |

Маршрутизация по сложности — дешёвый исполнитель на T0–T1 (проверки, сводки,
поиск), средний на T2 (реализация), старший на T3 (архитектура, контракты).
Решение — по классу задачи, а не по общему правилу «всегда самая дорогая».

## 6. Живой след

- **Журнал слайса** — `docs/current/WORKLOG.md`, append-only, живой лог
  работы внутри гейта.
- **След задачи** — агент пишет свой ход рассуждений сам, в
  `docs/current/agent-log/<task-id>.md`. Оркестратор переписку не перехватывает.
- **События** — по одной строке на событие (старт, коммит, вердикт) в
  `docs/current/events.jsonl`. По этому потоку панель показывает, что
  делается и каким агентом.

Уровни детализации: строка (почти бесплатно) · отчёт задачи (1–3 КБ) · полный
след (по запросу). Читать полный след заранее — платить за чужие рассуждения
без нужды.

## 7. Приёмка

PASS = **зелёный выход исполняемой команды**, а не проза и не «в контексте
выглядит правильно». Воспроизводит кто угодно в любой сессии. Подробности —
`LUNERA_STANDARDS.md` §3.1.

Ревью — на архитектуру и риск, а не на то, что ловит линтер. Дёшевые
автоматические проверки (формат, линт, типы, тесты, fitness) — на каждое
изменение, блокируют. Ревью — на то, что автоматика не ловит.
