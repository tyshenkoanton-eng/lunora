# S3b-14 · Портретный путь: гарантия приватности по домену, а не по списку форм

**Гейт:** G17-S3b · **Карточка:** [../G17-S3b-план.md](../G17-S3b-план.md) · **Статус:** контракт записан по P1 критики ревью S3b-09 (критерий (в) контракта не выполнен)
**Способ:** `TASK_CONTRACT.md` · **Контур:** `EXECUTION_PROTOCOL.md` · **Ревью:** `REVIEWER_CHARTER.md`

TASK      : Сделать гарантию «в пакете портрета нет ПДн» независимой от того, какими формами записаны ПДн. Сейчас пакет портрета собирает из карты ровно три значения — `chinese.year_animal`, `chinese.day_master_element`, `numerology.life_path` — и подставляет их дословно (`src/lunora/interpret/portrait.py`). Проверка приватности построена на списке форм (маркеры + 4 паттерна): подложенный e-mail в `year_animal` **реально доходит до пакета**, детектор молчит, приватные тесты остаются зелёными — то есть контрактный критерий (в) («подложенная ПДн, дошедшая до пакета портрета, роняет набор») формально не выполнен для форм вне списка. Нужна **доменная** проверка: значения, которые сборка берёт из карты, должны лежать в своём домене — год зверя ∈ множество 12 животных, стихия ∈ множество 5 стихий, `life_path` — целое число в допустимом диапазоне. Тогда любая подмена поля (e-mail, телефон, произвольный текст, пустая строка) ловится независимо от формы, а гарантия перестаёт зависеть от полноты списка форм.
ВХОД      : `tests/test_llm_portrait_privacy.py` (read-only), `src/lunora/interpret/portrait.py` (read-only), `src/lunora/engines/calc/engine.py` (read-only — источники `year_animal` и `day_master_element`), `src/lunora/engines/numerology.py` (read-only — источник `life_path`), `tests/test_calc.py` (read-only — уже есть фикстуры значений домена).
ГРАНИЦЫ   : Запись — `tests/test_llm_portrait_privacy.py`, `docs/current/agent-log/S3b-14.md`. **Read-only:** `src/**`, `scripts/**`, `docs/grillmax/**`, `docs/current/ROADMAP_STATUS.yaml`, `Makefile`, `tests/test_llm_privacy.py` (если задача S3b-13 уже вынесла общий детектор — согласуйся: доменная проверка всё равно живёт в портретном тесте; общий модуль детектора S3b-13 не трогай).
            Продуктовый код не трогать. Домены бери из кода, а не выдумывай: множество животных — в `engine.py` (12), множество стихий (5) — там же, диапазон `life_path` — из `numerology.py` и подтверждён `tests/test_calc.py`.

КРИТЕРИЙ  : (а) тест проверяет домен каждого из трёх подставляемых значений — год зверя, стихия, `life_path`; (б) подмена **любого** из трёх полей на произвольный текст (e-mail, телефон, ФИО, пустая строка, «Null») роняет набор — минимум пять подмен, по каждому полю; (в) проверка домена не зависит от списка форм ПДн: удаление или сужение детектора не должно делать доменную проверку зелёной; (г) домены взяты из кода: тест падает, если в `engine.py`/`numerology.py` изменится множество животных или стихий (то есть тест следит за доменом, а не за его копией); (д) «красным»: не менее пяти зафиксированных мутаций, каждая — с выводом pytest в agent-log.
СКИЛЛ     : python, pytest — стандартная библиотека, новых зависимостей не добавлять.
