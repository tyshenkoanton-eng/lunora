# S3b-15 · Гейт `slice-check-s3b`: fail-closed на неполном наборе и закреплённый интерпретатор

**Гейт:** G17-S3b · **Карточка:** [../G17-S3b-план.md](../G17-S3b-план.md) · **Статус:** контракт записан по P1 критики ревью S3b-12 и её находкам Н1, Н2
**Способ:** `TASK_CONTRACT.md` · **Контур:** `EXECUTION_PROTOCOL.md` · **Ревью:** `REVIEWER_CHARTER.md`

TASK      : Сделать так, чтобы гейт `make slice-check-s3b` не мог стать зелёным, не проверив приватность и дрейф порогов. Три части: (1) **fail-closed на неполном наборе** — сейчас цель проверяет только наличие ФАЙЛА набора (`if [ -f … ]`), поэтому удаление или переименование набора даёт «пропущен» и зелёный выход; набор, у которого все тесты помечены `skip`, тоже даёт зелёный выход (`pytest` exit 0 на «1 skipped»). Условие прохождения должно быть: набор существует, **непуст** (в нём есть выполненные тесты) и **не выключен** (не целиком skip/xfail); (2) **пин интерпретатора** — рецепт зовёт `pytest` и `python` из `PATH`, поэтому «зелёный выход» гейта зависит от окружения вызывающего (в чистом `env -i` — «pytest: not found»); проверки должны идти через закреплённый интерпретатор проекта; (3) **песочница в тесте должна копировать все три набора** — `tests/test_llm_cost.py::_make_sandbox` копирует только `tests/test_llm_cost.py` и требует `make slice-check-s3b` → exit 0; именно это упирается в строгий вариант цели. Песочница должна копировать все три набора, чтобы строгая цель проходила честно.
ВХОД      : `Makefile` (цель `slice-check-s3b`), `tests/test_llm_cost.py` (часть с `_make_sandbox`), `scripts/spike/llm_cost.py` (read-only), требование «slice-check работает без сети и без ключей» — `docs/current/G17-S1-план.md` § «make slice-check».
ГРАНИЦЫ   : Запись — `Makefile` (только цель `slice-check-s3b` и, если нужно, `.PHONY`), `tests/test_llm_cost.py` (только песочница `_make_sandbox` и её тесты), `docs/current/agent-log/S3b-15.md`. **Read-only:** `scripts/spike/**`, остальные `tests/**` (в т.ч. `tests/test_llm_privacy.py`, `tests/test_llm_cost_thresholds.py`, `tests/test_llm_portrait_privacy.py`), `src/**`, `docs/grillmax/**`, `docs/current/ROADMAP_STATUS.yaml`, `pyproject.toml`.
            **Накопительный `slice-check` не трогать:** `slice-check-s3b` в него не входит, пока нет артефакта живого замера — это отдельная задача (S3b-07). Рецепты — с ТАБУЛЯЦИЕЙ.
ПРОВЕРКА  : (из корня рабочего каталога задачи — worktree)
            `make -n slice-check-s3b` — показывает все три набора и вызов скрипта.
            `make -n slice-check | grep -c slice-check-s3b` — **0**.
            `PYTHONPATH=src /opt/dashboard/venv-lunora/bin/python -m pytest -q tests/test_llm_cost.py tests/test_llm_privacy.py tests/test_llm_cost_thresholds.py` — зелёный выход.
            `PATH=/opt/dashboard/venv-lunora/bin:$PATH make slice-check-s3b` — зелёный выход без артефакта замера, без сети и без ключей.
КРИТЕРИЙ  : (а) удаление набора → цель падает; (б) переименование набора → цель падает; (в) набор, у которого все тесты `skip` → цель падает; (г) пустой набор (0 тестов) → цель падает; (д) зелёный набор → цель зелёная; (е) цель не зависит от `PATH`: с очищенным окружением и без venv в `PATH` цель даёт внятную ошибку, а не «pytest: not found»; (ж) накопительный `slice-check` по-прежнему не содержит `slice-check-s3b`; (з) «красным»: не менее шести зафиксированных мутаций (удаление, переименование, skip-набор, пустой набор, поломка интерпретатора, подмена песочницы), каждая — с выводом в agent-log.
СКИЛЛ     : make, shell, python, pytest.
