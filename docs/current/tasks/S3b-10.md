# S3b-10 · Гард порогов: зелёное состояние пересчёта, опора R-05, provenance

**Гейт:** G17-S3b · **Карточка:** [../G17-S3b-план.md](../G17-S3b-план.md) · **Статус:** контракт записан по замечаниям ревью S3b-02 (1, 2б, 4) и находкам критики
**Способ:** `TASK_CONTRACT.md` · **Контур:** `EXECUTION_PROTOCOL.md` · **Ревью:** `REVIEWER_CHARTER.md`

TASK      : Довести гард дрейфа порогов до состояния, при котором легитимный пересчёт R-05 (задача S3b-06) не требует правки гарда, и убрать из него рыхлые места. Четыре части: (1) **зелёное состояние пересчёта** — синхронное обновление документа и JSON (включая переход `null` → число) должно оставлять гард зелёным; сейчас пороги с `null` и «absent`-опоры (§3.5 обязан не содержать «R-05») роняют гард после пересчёта, и обновлением JSON это не лечится; (2) **опора R-05** — сузить до конкретной величины, а не membership «число есть среди 18 чисел фрагмента §4»: сейчас посторонняя строка «Прочие операционные | 10 000 ₽» внутри фрагмента даёт ложно-зелёный результат, а косметическая правка соседней ячейки («55 тыс. ₽/год» → «55 000 ₽/год») сдвигает границу фрагмента и молча добавляет в принимаемые числа; (3) **provenance** — гард не читает объявленные в JSON `source`/`note`, а фактически опирается ещё и на §4; расхождение «заявленный источник ↔ фактически охраняемый» не ловится; (4) перечислить принимаемые форматы записи чисел в докстринге (гигиена, из замечания ревьюера).
ВХОД      : `tests/test_llm_cost_thresholds.py`, `scripts/spike/llm_cost_thresholds.json` (**read-only**), `docs/grillmax/05_business.md` §3.1/§3.5/§4 (**read-only**), `docs/grillmax/01_context.md` §4.3 (**read-only** — там определение бюджета 10 000 ₽/мес, откуда связь §4 и R-05), `docs/current/G17-S1-план.md` (**read-only**).
ГРАНИЦЫ   : Запись — `tests/test_llm_cost_thresholds.py`, `docs/current/agent-log/S3b-10.md`. **Read-only:** `scripts/spike/llm_cost_thresholds.json`, `scripts/spike/llm_cost.schema.json`, `docs/grillmax/**`, `docs/current/G17-S1-план.md`, `src/**`.
            Числа порогов не менять; гард ловит дрейф, а не правит его.
ПРОВЕРКА  : (из корня рабочего каталога задачи — worktree)

КРИТЕРИЙ  : (а) синхронная правка документа и JSON, включая переход `null` → число, оставляет гард **зелёным**; (б) посторонняя строка с «10 000 ₽» вне опоры и косметическая правка соседней ячейки §4 **не** делают гард зелёным; (в) правка самого порога в документе или в JSON по-прежнему роняет гард — в обе стороны; (г) гард проверяет, что объявленный в JSON `source` совпадает с фактически охраняемыми источниками, и падает при расхождении; (д) «красным»: не менее пяти зафиксированных мутаций (две на дрейф, две на ложно-зелёное, одна на пересчёт), каждая — с выводом pytest в agent-log.
СКИЛЛ     : python, pytest — стандартная библиотека.
РЕВЬЮ     : Слепой ревьюер: «гард ловит дрейф в обе стороны и не даёт ложной тревоги ни на пересчёте, ни на косметике». Критик ревью — обязателен.
