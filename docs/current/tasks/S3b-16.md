# S3b-16 · Валидатор артефакта: обе клаузы определения объектного узла и fail-closed на неразобранной форме

**Гейт:** G17-S3b · **Карточка:** [../G17-S3b-план.md](../G17-S3b-план.md) · **Статус:** контракт записан по находкам критики ревью S3b-11 (P2-1, P2-3, P2-4)
**Способ:** `TASK_CONTRACT.md` · **Контур:** `EXECUTION_PROTOCOL.md` · **Ревью:** `REVIEWER_CHARTER.md`

TASK      : Закрыть в валидаторе артефакта три места, где задокументированное поведение не защищено тестом. (1) **Первая клауза определения объектного узла** (`"object" in type`) — мутация `if "object" in names:` → `if False:` оставляет набор зелёным: поведение верное, но именно эта клауза не закреплена. (2) **Вторая клауза** (`return any(key in schema …)` для узлов с `properties`/`required`/`additionalProperties` без `type`) — мутация `return any(...)` → `return False:` тоже оставляет набор зелёным: узлы без `type` (валидные по спецификации) не защищены. (3) **fail-closed на неразобранной форме** — ветки «форма не разобрана» возвращают политику `"forbid"`; замена на `"allow"` оставляет набор зелёным, хотя докстринг прямо объявляет: пока форма не разобрана, лишние поля считаются запрещёнными — это строже, а не мягче. Добавить тесты, которые роняют набор при каждом из трёх отключений.
ВХОД      : `scripts/spike/llm_cost.py` (валидатор: определение объектного узла, политика `additionalProperties`, ветки неразобранной формы), `tests/test_llm_cost.py` (текущие фикстуры схемы), `scripts/spike/llm_cost.schema.json` (боевая схема — **read-only**).
ГРАНИЦЫ   : Запись — `scripts/spike/llm_cost.py`, `tests/test_llm_cost.py`, `docs/current/agent-log/S3b-16.md`. **Read-only:** `scripts/spike/llm_cost.schema.json`, `scripts/spike/llm_cost_thresholds.json`, `Makefile`, `src/**`, `docs/grillmax/**`, `docs/current/ROADMAP_STATUS.yaml`, остальные `tests/**`.
            Поведение `--check` по существу не менять: код выхода 0 на артефакте в бюджете, 1 на битом/превышении; формат сообщений прежний. Обратная совместимость с боевой схемой не должна ломаться (у всех шести объектных узлов боевой схемы `additionalProperties: false`).
ПРОВЕРКА  : (из корня рабочего каталога задачи — worktree)
            `PYTHONPATH=src /opt/dashboard/venv-lunora/bin/python -m pytest -q tests/test_llm_cost.py` — зелёный выход.
            `PYTHONPATH=src /opt/dashboard/venv-lunora/bin/python -m ruff check scripts/spike/llm_cost.py tests/test_llm_cost.py` — зелёный выход.
КРИТЕРИЙ  : (а) отключение первой клаузы определения объектного узла роняет набор; (б) отключение второй клаузы — тоже; (в) замена fallback-политики `"forbid"` на `"allow"` роняет набор; (г) поведение на боевой схеме не изменилось: побайтово тот же stdout и те же коды выхода на эталонном артефакте (в бюджете / лишнее поле / превышение / битый JSON); (д) «красным»: не менее трёх зафиксированных мутаций, каждая — с выводом pytest в agent-log.
СКИЛЛ     : python, json, pytest — только стандартная библиотека, новых зависимостей не добавлять.
РЕВЬЮ     : Слепой ревьюер: «задокументированное поведение защищено тестом». Безопасник — отдельный проход: «в тестовых копиях схемы нет ключей и реальных данных». Критик ревью — обязателен.
