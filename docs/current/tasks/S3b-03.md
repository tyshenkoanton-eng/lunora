TASK      : Реализовать `scripts/spike/llm_cost.py` с режимом `--check`: без сети и без ключей проверить артефакт `docs/current/spike/llm_cost.json` по схеме `scripts/spike/llm_cost.schema.json` и сверить его с порогами `scripts/spike/llm_cost_thresholds.json`. Дополнительно объявить цель `make slice-check-s3b`.
ВХОД      : `scripts/spike/llm_cost.schema.json` и `scripts/spike/llm_cost_thresholds.json` (зафиксированы оркестратором — **read-only**), требование «сверка без вызова API» — `docs/current/G17-S1-план.md` § «make slice-check», формат соседнего артефакта-протокола — `docs/current/spike/payment_smoke.md`.
ГРАНИЦЫ   : Запись — новый `scripts/spike/llm_cost.py`, `Makefile` (цель `slice-check-s3b`), новый `tests/test_llm_cost.py`, `docs/current/agent-log/S3b-03.md`. **Read-only:** схема, пороги, `docs/grillmax/**`, `src/**`, `docs/current/ROADMAP_STATUS.yaml`.
            **Накопительный `slice-check` не трогать.** До живого замера артефакта нет, и гейт не должен краснеть из-за отсутствующего замера — в накопительный список `slice-check-s3b` входит только вместе с артефактом (задача S3b-07).
            **В `--check` не ходить в сеть** ни при каких флагах и не требовать ключей: это проверка артефакта, а не замер.
ПРОВЕРКА  : (из корня рабочего каталога задачи — worktree) `PYTHONPATH=src /opt/dashboard/venv-lunora/bin/python scripts/spike/llm_cost.py --check` — код выхода 0 на артефакте в бюджете, 1 в остальных случаях.
            `PYTHONPATH=src /opt/dashboard/venv-lunora/bin/python -m pytest -q tests/test_llm_cost.py` — зелёный выход.
            `PYTHONPATH=src /opt/dashboard/venv-lunora/bin/python -m ruff check scripts/spike/llm_cost.py tests/test_llm_cost.py` — зелёный выход.
КРИТЕРИЙ  : (а) артефакта нет → понятное сообщение и ненулевой код выхода; (б) артефакт невалиден по схеме → ненулевой код выхода с указанием поля; (в) артефакт превышает порог варианта → ненулевой код выхода со значением и порогом; (г) артефакт в бюджете → код выхода 0; (д) пороги берутся из файла, а не зашиты в код; (е) тесты покрывают все четыре случая на фикстурах; (ж) `make slice-check-s3b` вызывает скрипт и падает при превышении; (з) `--check` не требует ни ключа, ни сети: тест это проверяет (например, запуском с пустым окружением).
СКИЛЛ     : python, json, pytest, make. Новых зависимостей в проект не добавлять — валидация по схеме пишется на stdlib.
РЕВЬЮ     : Слепой ревьюер: «чекер честный — не проходит на плохом артефакте, не проходит при отсутствии артефакта, пороги берёт из файла». Безопасник — отдельный проход: «в скрипте нет обращения к секретам, в тестовых фикстурах нет ключей и реальных ПДн». Критик ревью — обязателен.
