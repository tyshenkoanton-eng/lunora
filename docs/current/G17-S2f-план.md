# План G17-S2f — доводка интеграции P3

**Дата:** 2026-11-22 · **Открыт:** по go Антона (2026-11-22, тред «Доводка интеграции P3 (G17-S2f)»)
**Источник правды по слайсу.** Основание — внешнее ревью ядра, принятое Антоном: **точка P3
понижена до CONDITIONAL** (не закрыта). Close-record, который это меняет, —
[../gates/G17-S2e-close.md](../gates/G17-S2e-close.md). Платёжную часть S3a (PR #18) слайс не трогает.

## Зачем

Движки S2a–S2d доказаны на golden по отдельности (`resolve()` → `engine.chart()`), но рантайм-склейка
S2e (`calc.engine.calculate(BirthData)` → `onboard` → хранимая карта → LLM) теряет часть того, что
движки умеют: точность времени не превращается в интервал, `place_id`/регион не доходят до реестра
спорных поясов, пол и ФИО не входят в `BirthData`, `stability` в хранимой карте нет. Ревью (F01–F11)
требует доказать ядро **сквозь** рантайм, а не только на уровне движка.

## Правило слайса

**Каждый фикс = сквозной тест** через `calculate(BirthData)` и/или `POST /api/onboard` (на настоящей
PostgreSQL, как в S3a), а не только через `resolve()`/`engine.chart()`. Тесты раньше кода (красные →
зелёные). `make verify` зелёный на каждом шаге.

## Решения Антона (2026-11-22, по F04) — обязательны

1. **Нумерология — два контура: по дате И по полному имени (ФИО).** `BirthData` обязан нести ФИО
   при рождении (фамилия/имя/отчество, §1.1 NUMEROLOGY-RULES); контур имени включает **анализ
   изменения имени** (`name_current` → второй набор + дельта, §3.5). В `NumerologyChart` идут
   `EXPRESSION`/`HEART`/`PERSONA`/`MATURITY`. «MATURITY без ФИО» больше не кейс — ФИО обязателен;
   fail-closed (F09) остаётся для латиницы/смешанного алфавита.
2. **Пол — обязательное поле `BirthData`.** Да-юнь Ба-Цзы проводится в `ChineseChart`.
3. **152-ФЗ.** Имя и пол — ПДн: входят в детерминированные движки и в хранимую карту, но **не**
   уходят в LLM-пакет и **не** в аналитику. В LLM — только градусы + текст (без имени, даты, места,
   пола). Тест-сторож пакета LLM падает, если в пакете есть имя или пол (а также дата, время, место,
   координаты).

## v1-контракт хранимой карты (F04)

Каждая величина четырёх школ в хранимой карте — либо значение со `stability`, либо явный
`not_computed` с причиной из ENGINE-SPEC §1.2. «Молчаливого» пропуска и `computed(None)` нет.

| Школа | Величина | v1 |
|---|---|---|
| Западная | знаки и градусы 10 тел + истинные узлы | значение + `stability` |
| | ASC/MC, дома Плацидуса, дом тела | значение + `stability`; без времени — `no_birth_time`; **полярные широты (> 66,56°) — `not_applicable_latitude`** (не подменяем Порфирием, как astro.com; UX-объяснение — позже) |
| | дома по цельным знакам | значение + `stability`; без времени — `no_birth_time` |
| | аспекты §3.7 | список + `stability` набора аспектов |
| Ведическая | раши/накшатра/пада грах, лагна, бхава | значение + `stability` + отдельный флаг `near_boundary` (F11) |
| | Вимшоттари (последовательность МД, активная МД/АД) | значение + `stability`; без времени — `no_birth_time` |
| Ба-Цзы | столпы года/месяца | значение + `stability` (ли-чунь/цзе на интервале, F03) |
| | столпы дня/часа | значение + `stability`; без времени — `no_birth_time` |
| | да-юнь (направление, вход, декады) | значение + `stability` (нужен пол — теперь обязателен); без времени — `no_birth_time` |
| | `element_balance` | **переименован в `visible_stem_counts`** (счёт стихий только видимых стволов, F10); полный баланс §5.7 со скрытыми стволами — S4 |
| Нумерология | контур даты (LIFE_PATH, BIRTHDAY, квадрат, вершины/вызовы/периоды) | как в S2a; квадрат после 2000 — `rule_not_formalized` (решение №2) |
| | контур имени (EXPRESSION/HEART/PERSONA, MATURITY) | значение; латиница/смешанный алфавит — явный `not_computed` (F09) |
| | изменение имени (`name_current`) | второй набор + дельта (изменилось/нет), без «лучше/хуже» (§3.5, §8) |
| Все | **вне v1** (явно перечислены в карте `not_computed: out_of_v1`/`rule_not_formalized`) | достоинства, Жребий, профекции; йоги, шад-бала, сад-сати; скрытые стволы, десять богов, сила ГД, юншэнь; `KARMIC_DEBT_CHECK` |

## Фиксы и сквозные тесты

| # | Что | Сквозной тест (через `calculate`/`onboard`) | Критерий |
|---|---|---|---|
| **F01** | `precision` → интервал допуска: `exact` ±0, `approximate_30` ±30, `approximate_60` ±60, `approximate` ±180 (ARCH §4.5 «± 3 часа»), `unknown` — сутки. Дискретные величины → `stable`/`range`/`undetermined` с вариантами | карта A ±30 и ±60 — асцендент/столп часа/лагна становятся `range` с двумя вариантами там, где граница внутри интервала; повторённый час (fold, Москва осень) — две гипотезы смещения доходят до карты | значения и теги совпадают с поиском границ напрямую по `resolve()` |
| **F02** | `place_id`/регион через API → `BirthData` → `resolve` → хранимая модель (`users`, `calculation_runs`) | `POST /api/onboard` для Джизака (TZD-001), Тирасполя и Бендер (TZD-002) — в провенансе две гипотезы и `dispute_id`; места добавлены в минимальный справочник | обе гипотезы видны в ответе и в БД |
| **F03** | ли-чунь/цзе при неизвестном часе — проверка на всём суточном интервале | дата ли-чунь без времени → столп года/месяца `range` (два варианта), а не значение по опорной точке | регрессия: раньше — `stable` |
| **F04** | v1-контракт (таблица выше), пол и ФИО в `BirthData`, да-юнь и числа имени в карте | `calculate` для каждой школы: каждая величина v1 либо посчитана, либо `not_computed` с причиной | тест-перечень величин контракта |
| **F05** | `stability` через поиск границ по непрерывной угловой скорости (адаптивный шаг от расстояния до границы и скорости угла), вместо сетки 10 мин | property-тесты на широтах 65–67°: результат совпадает с плотным перебором; на быстро бегущем асценденте сетка 10 мин пропускает смены, новый поиск — нет | 0 расхождений на выборке |
| **F06** | LLM-защита для `approximate_30/60`: в пакет идут только `stable`; `range` — как «A или B»; `undetermined` и не посчитанное — не идут | пакет LLM для карты ±60 не содержит однозначного ASC/дома, если они `range`/`undetermined` | тест на пакете |
| **F07** | `CalculationRun` фиксирует полное происхождение: зона, точность и допуск, `place_id`/регион, `dispute_id`, UTC-гипотезы, `tz_build`, эфемериды, версии правил движков; `input_hash` — HMAC с серверным перцем, не голый SHA-256 (ARCH §3.2) | `onboard` → строка `calculation_runs` с полным провенансом | миграция 003 + тест на PG |
| **F08** | происхождение карты E: «rule-derived (§5.4) + cnlunar», не «ручная сверка bazi.biz» (TST-вариант E не снят) | golden E и close-record S2b поправлены; `golden_audit` зелёный | текст источника совпадает с фактом съёма |
| **F09** | `Result.computed(None)` запрещён контрактом; MATURITY/HEART/PERSONA без значения — явный `not_computed` | `Result.computed(rule, None)` падает; латиница в ФИО через `calculate` → `not_computed` | тест контракта |
| **F10** | `element_balance` → `visible_stem_counts` | `calculate` → `ChineseChart.visible_stem_counts`; в LLM подпись «видимые стволы» | старого ключа нет |
| **F11** | ведический `stability`: «близко к границе» (`near_boundary`) ≠ «две величины на интервале» (`range`) | точное время у границы — `stable` + `near_boundary`; ±60 через границу — `range` | раздельные поля |
| **152-ФЗ** | тест-сторож LLM-пакета | пакет `generate_response`/портрета не содержит ФИО, формы имени, пола, даты/времени/места/координат | падает при утечке |

## Шаги (каждый — коммит + запись в WORKLOG)

1. Открытие слайса: план, статус (P3 → CONDITIONAL), board.
2. Сквозные тесты F01–F11 + сторож LLM (красные).
3. Контракт и вход: `Result` без `computed(None)` (F09); `BirthData` + пол/ФИО/`place_id`/регион;
   нумерология имени и изменения имени; да-юнь (F04); `visible_stem_counts` (F10).
4. Интервалы: поиск границ по угловой скорости (F05); `precision` → допуск, сигналы `stability` по
   всем школам (F01, F03, F11); полярные дома — `not_applicable_latitude`.
5. Рантайм: API/схема/модели/миграция 003 (F02, F07); LLM-пакет из `stability` (F06) и сторож ПДн.
6. Происхождение карты E (F08), close-records (S2b, S2e) честно, вердикт P3, changelog, статус, board.

## Вне scope

Полный продуктовый справочник мест (добавляем только места спорных поясов); UX объяснения развилок
и полярных домов; подтверждение мягких проверок ФИО пользователем (§1.4) — движок отдаёт
предупреждения в карте, экран подтверждения — фронт; шифрование ПДн в БД (ARCH §7.3); слой
интерпретации (хвост `interpret/planets.py`); S4-величины; живой смоук S3a; S3b (LLM-замер).

## Открытые вопросы (вынесены координатору, работа идёт по рекомендации)

- **В-1. ФИО латиницей/смешанным алфавитом на онбординге.** Рекомендация: `POST /api/onboard`
  отвечает 422 с кодом (`latin_not_supported`/`mixed_script`, §1.3 — «отказ с просьбой ввести
  кириллицей»), карта не сохраняется; на уровне движка (`calculate` вне API — пересчёты, прогнозы)
  контур имени и MATURITY → явный `not_computed` с новой причиной `name_not_supported` (в закрытом
  списке ENGINE-SPEC §1.2 подходящей нет — список расширяется на одну причину).
