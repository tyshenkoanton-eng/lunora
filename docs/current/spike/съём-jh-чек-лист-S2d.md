# Чек-лист ручного съёма Jagannatha Hora — G17-S2d

**Кто:** Антон (Windows) · **Дата:** 2026-11-21 · **Связано:** [карточка G17-S2](../G17-S2-план.md) (под-слайс S2d), кейсы GV-01…GV-06 и спайк П-2 из `ENGINE-SOURCES.md`

Jagannatha Hora (JH) — эталон ведического движка. Сначала записываем **настройки** JH (шаг 1, это спайк П-2). Если их не знать, любое расхождение в датах даш нельзя объяснить: другая длина года даш или другой вариант айанамши тихо сдвигают даты на недели. Потом снимаем три карты (шаг 2).

## Общие правила

1. **Имя:** везде `Тест`. Своё имя не вводите: имя — это ПДн (152-ФЗ).
2. **Место:** не выбирайте город из атласа JH. Введите **координаты и пояс вручную** из таблицы шага 2, чтобы JH считал ровно тот же вход, что и мы.
3. **Летнее время:** поле DST ставьте 0. Смещение в таблице уже включает летнее время на дату.
4. **Настройки между картами не меняйте.** Все три карты снимаются с одними настройками, теми, что JH ставит по умолчанию (шаг 1).
5. **Наших значений в чек-листе нет намеренно.** Эталон снимается вслепую.
6. **Файл:** скриншот `<карта>-jh-<что>.png` (например, `A-jh-grahas.png`). Присылайте в чат проекта. В git ляжет только расшифровка и SHA-256 файла.

## Шаг 1 — настройки (П-2)

Откройте настройки расчёта JH (меню Preferences / Calculation options) и **ничего не меняйте**. Запишите название каждого пункта точно так, как оно написано в JH, и сделайте скриншот каждого окна настроек (`jh-settings-1.png`, …).

| Что записать | Значение в JH |
| --- | --- |
| Версия JH (Help → About) | |
| Айанамша — точное название варианта (например, «Lahiri», «Chitrapaksha», «True Chitrapaksha») | |
| Узлы Раху/Кету — средний (mean) или истинный (true) | |
| Определение года для даш (длина года: например, 365,2425 сут, сидерический солнечный год, 360 сут и т. п.) | |
| Система бхав, если есть выбор (нужны цельные знаки / Rasi) | |
| Если JH показывает значение айанамши на момент карты — его тоже (см. шаг 2) | |

## Что будет дальше

Я расшифрую скриншоты в `tests/golden/evidence/` и заведу кейсы GV-01…GV-06. В `settings` каждого кейса пойдут записанные настройки JH, в `versions.reference_service` — версия JH. Если вариант айанамши или длина года у JH отличаются от наших (Лахири № 1, §2.7), это не подгоняется: я посчитаю, какой сдвиг даёт разница, и отнесу расхождение к классу «настройки эталона». Если объяснить расхождение не удастся, кейс пойдёт в `disputed` с разбором.
