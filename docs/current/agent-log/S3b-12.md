## 3. Решения и почему

### 3.1. Рецепт — четыре строки, каждая самодостаточна

```
slice-check-s3b: ## G17-S3b: офлайн-гарды LLM — приватность пакета, дрейф порогов, сверка замера с порогами R-05 (docs/current/G17-S3b-план.md); без сети, ключей и артефакта замера; PYTHONPATH=src — код из рабочего дерева
	if [ -f tests/test_llm_privacy.py ]; then PYTHONPATH=src pytest -q tests/test_llm_privacy.py; else echo "slice-check-s3b: нет набора tests/test_llm_privacy.py — пропущен"; fi
	if [ -f tests/test_llm_cost_thresholds.py ]; then PYTHONPATH=src pytest -q tests/test_llm_cost_thresholds.py; else echo "slice-check-s3b: нет набора tests/test_llm_cost_thresholds.py — пропущен"; fi
	if [ -f tests/test_llm_cost.py ]; then PYTHONPATH=src pytest -q tests/test_llm_cost.py; else echo "slice-check-s3b: нет набора tests/test_llm_cost.py — пропущен"; fi
	if [ -f docs/current/spike/llm_cost.json ]; then python scripts/spike/llm_cost.py --check; else echo "slice-check-s3b: нет артефакта docs/current/spike/llm_cost.json — сверка с порогами ждёт живого замера (S3b-04)"; fi
```

Одна строка — одна проверка, как в остальных целях репозитория. `make -n
slice-check-s3b` показывает и скрипт, и все три набора, поэтому критерий (а)
проверяется глазами по сухому прогону. Рецепты с ТАБУЛЯЦИЕЙ — как во всех остальных
целях (`cat -A` показывает `^I`).

### 3.2. Скрипт `--check` — под артефактом

Критерий (г) требует, чтобы цель не требовала артефакта живого замера, а критерий
(а) — чтобы скрипт был в цели. Оба выполняются, если вызов стоит **под проверкой
наличия артефакта**: пока `docs/current/spike/llm_cost.json` не существует, цель
печатает, что сверка ждёт живого замера (S3b-04), и остаётся зелёной; как только
артефакт появляется, `--check` выполняется и может покраснить цель (доказано,
раздел 5.2).

Почему не «запустить и простить»: чекер при отсутствии артефакта печатает `FAIL нет
артефакта` и выходит с кодом 1 — это тот же код, что и «артефакт вне бюджета».
Отличать их пришлось бы разбором вывода — хрупко и нечитаемо.

Почему не «запустить всегда»: до S3b-04 артефакта нет, и гейт краснел бы из-за
отсутствующего замера — ровно то, чего контракт не хочет (и что в S3b-03 было
записано как «накопительный `slice-check` не трогать»).

### 3.3. Набор, которого нет, — пропускается, а не роняет цель

Read-only набор `tests/test_llm_cost.py` строит «песочницу make»: копирует
настоящий `Makefile`, скрипт, схему, пороги и **только** `tests/test_llm_cost.py`
(заглушка), после чего требует, чтобы `make -C <песочница> slice-check-s3b` вышел
с кодом 0 (`test_make_target_passes_when_budget_is_met`) и с ненулевым кодом при
артефакте вне бюджета (`test_make_target_fails_when_budget_is_exceeded`).

Жёсткий `pytest -q tests/test_llm_privacy.py tests/test_llm_cost_thresholds.py
tests/test_llm_cost.py` в песочнице падает: pytest на отсутствующем файле даёт
`ERROR: file or directory not found` и код выхода 4 — оба теста песочницы
краснеют, а с ними и весь набор `tests/test_llm_cost.py`, который входит в
ПРОВЕРКУ контракта. Поэтому набор запускается, если файл есть, а отсутствие файла
печатается вслух и гейд не роняет.

**Честное ограничение (ослабление гейта):** если файл набора удалить, цель останется
зелёной. Строгий вариант («нет файла набора → красный») возможен, когда песочница
make будет содержать все три набора, — а `tests/test_llm_cost.py` в зоне записи
задачи S3b-11. Это отмечено там, а не сделано здесь: `tests/**` в этой задаче
read-only.

### 3.4. `PYTHONPATH=src` в рецептах

Пакет `lunora` в venv на VPS не установлен (`import lunora` → ModuleNotFoundError),
поэтому `tests/test_llm_privacy.py` без `PYTHONPATH=src` не собирается вовсе. Кроме
того, в worktree установленный редактируемый пакет смотрел бы в `main`, а не в
ветку: гард проверял бы чужой код. Поэтому в рецептах набора стоит
`PYTHONPATH=src` — как и в ПРОВЕРКЕ контракта. Прочие цели репозитория этого не
делают: там предполагается `pip install -e .` (`make setup`). Это отступление от
соседей, но с явной причиной, и оно в самой строке рецепта видно.

### 3.5. Накопительный `slice-check` не тронут

Строка `slice-check:` осталась прежней — `slice-check-s3b` в неё не входит, пока
нет артефакта живого замера (задача S3b-07). Проверка контракта это фиксирует:
`make -n slice-check | grep -c slice-check-s3b` → `0`.

## 4. Что пробовал и что отбросил

- **Жёсткий один pytest со всеми тремя файлами.** Отбросил: роняет read-only
  песочницу make (раздел 3.3).
- **`$(wildcard tests/test_llm_*.py)`.** Тот же эффект, но ослабление не видно ни в
  `make -n`, ни в коде; к тому же зацепило бы четвёртый набор `tests/test_llm.py`,
  которого в контракте нет. Отбросил.
- **Один `pytest -q` на каталог `tests/`.** Отбросил: увёл бы гейт в полный прогон
  тестов, включая требующие PostgreSQL и сети, — против критерия (г).
- **Живой смоук `--measure` в цели.** Отбросил: нужен ключ и сеть, критерий (г)
  прямо это запрещает.
- **`slice-check-s3b` в накопительный `slice-check`.** Отбросил: контракт запрещает
  до артефакта замера (S3b-07).

## 6. Что осталось за границами (не чинил, не менял поведение)

1. **Удалённый файл набора не роняет гейд** (раздел 3.3). Строгий вариант требует
   правки песочницы в `tests/test_llm_cost.py` — зона записи S3b-11.
2. **`r05` не сверяется никогда** — печатается `SKIP`: экстраполяция на 5 000 MAU
   требует долей и активности из расчёта G1 §4.3. Зелёный `--check` ≠ «R-05 в
   бюджете» (из плана гейта, отдельные задачи S3b-05/S3b-06).
3. **`slice-check-s3b` не входит в накопительный `slice-check`** — по контракту,
   до артефакта живого замера (S3b-07).
4. **Живой смоук (`--measure`) в гейт не входит** — ключи и сеть вне контракта.
5. **Рецепты зовут `python` и `pytest`**, как все остальные цели репозитория: на VPS
   нужен venv в `PATH` (`/opt/dashboard/venv-lunora/bin`). Путь вендора в
   `Makefile` не зашивал — это свойство машины, а не репозитория.
6. **Чекер доверяет числам артефакта** и не пересчитывает стоимость из `usage` ×
   `pricing`; подлинность артефакта — дело S3b-04 (из плана гейта).
