# Сценарий 1. Потерян компьютер

Сломался диск, украли ноутбук, залили кофе. Доступ к Claude при этом есть.

## Что уцелело

| Источник | Что там | Свежесть |
|---|---|---|
| **GitHub** `git@github.com:tyshenkoanton-eng/lunora.git` | код и все документы, включая прототип и снимок отметок проверки | последний пуш в рабочую ветку |

## Шаг 1. Поставить инструменты

```bash

npm install -g @anthropic-ai/claude-code

# клиент Яндекс.Диска — скачать с disk.yandex.ru и войти
```

## Шаг 2. Забрать код и встать на рабочую ветку

```bash
mkdir -p ~/Projects && cd ~/Projects
git clone git@github.com:tyshenkoanton-eng/lunora.git
cd lunora
git checkout claude/recovery-lost-computer-a0vl5l   # ← обязательно: в main свежей работы ещё нет
```

Если ключ SSH остался на старом компьютере — через HTTPS:

```bash

```

Логин — учётная запись GitHub, пароль — токен из настроек GitHub, раздел Developer settings → Personal access tokens.

⚠️ `git clone` открывает ветку `main`, а вся последняя работа — в ветке `claude/recovery-lost-computer-a0vl5l` (на сегодня она более чем на сотню коммитов впереди `main`). Без `git checkout` на неё прототип и документы будут старыми.

## Шаг 3. Вернуть то, чего нет в GitHub

Дождаться синхронизации Яндекс.Диска, затем:

```bash

# исследования

# память Claude Code

cp -R "$Д/claude-настройки/memory" ~/.claude/projects/-Users-Lunera-Yandex-Disk-localized-VPN/
```

⚠️ Путь `-Users-Lunera-Yandex-Disk-localized-VPN` — это зашифрованное имя рабочей папки. Если имя пользователя на новой машине другое, папка памяти будет называться иначе: запустите Claude один раз, посмотрите, какая папка появилась в `~/.claude/projects/`, и кладите память туда.

# Сценарий 2. Потерян доступ к Claude

Заблокирована учётная запись, кончилась подписка, сервис недоступен. Компьютер при этом цел.

## Что происходит

| Что | Состояние |
|---|---|
| Файлы проекта | **целы**, лежат локально |
| Прототип как файл | **цел**: `docs/grillmax/wireframes/02-report.html` |
| Прототип по ссылке-артефакту | **недоступен** |
| Память Claude | цела на диске, но без Claude бесполезна |
| История переписки | цела в `.jsonl`, читается как текст |

🔑 Работа не потеряна. Потерян инструмент, которым её делали.

## Шаг 1. Открыть прототип без Claude

```bash
cd ~/Projects/lunora/docs/grillmax/wireframes

{ printf '<!doctype html><html lang="ru"><head><meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1"></head><body>\n'; \
  cat 02-report.html; \
  printf '\n</body></html>\n'; } > view.html

python3 -m http.server 8765
```

Открыть `http://localhost:8765/view.html` — прототип работает целиком, все экраны на месте.

⚠️ Обёртка нужна: файл хранится как фрагмент без заголовка страницы, и без неё браузер покажет кракозябры вместо кириллицы.

Отметки «проверено» в прототип возвращаются отдельно — см. раздел «Отметки проверки прототипа» ниже.

## Шаг 2. Восстановить доступ или сменить инструмент

**Если дело в подписке или блокировке:** новая учётная запись Claude ставится поверх тех же файлов, ничего переносить не нужно.

```bash
npm install -g @anthropic-ai/claude-code
cd ~/Projects/lunora && claude
```

Память при этом сохраняется — она лежит в `~/.claude/projects/`, а не в облаке Claude.

**Если нужен другой инструмент:** проект не привязан к Claude ничем, кроме удобства. Документы — обычный текст, прототип — обычный HTML. Любой редактор или другой помощник продолжит с того же места.

## Шаг 3. Прочитать историю работы

Переписка лежит в файле:

```
Яндекс.Диск/Лунора/claude-настройки/транскрипт-сессии.jsonl
```

Каждая строка — событие в формате JSON. Вытащить текст:

```bash
python3 - <<'PY'
import json
with open('транскрипт-сессии.jsonl') as f:
    for line in f:
        try: d = json.loads(line)
        except: continue
        m = d.get('message', {})
        c = m.get('content')
        if isinstance(c, str) and c.strip():
            print(f"\n=== {m.get('role','?')} ===\n{c[:2000]}")
PY
```

# Отметки проверки прототипа

Галочки «проверено / с замечанием» хранятся в браузере (`localStorage`) и в хранилище артефакта, привязанном к аккаунту Claude. В git они сами не попадают, поэтому их выгружают снимком.

**Снимок:** `docs/grillmax/review-progress.json` (формат кнопки «Экспорт»), рядом `review-progress.md` с инструкцией. Он в git, значит переживает и потерю компьютера, и потерю аккаунта.

**Вернуть отметки в прототип:** открыть прототип (локальный `view.html` или опубликованный артефакт) → в шапке панели проверки нажать **«Импорт»** → вставить всё содержимое `review-progress.json`. Отметки добавятся к текущим, ничего не сотрётся.

**Обновить снимок** (после новой большой проверки): в прототипе нажать **«Экспорт»**, скопировать код, заменить им содержимое `review-progress.json`, закоммитить и запушить. Снимок не обновляется сам.

# Что нужно держать в порядке

| Действие | Когда |
|---|---|
| `git add -A && git commit -m "работа $(date +%F)" && git push` | после каждого дня работы |
| снять снимок отметок: «Экспорт» → заменить `review-progress.json` → commit + push | после большой проверки |
| `cp -R ~/Projects/lunora/docs/ "$HOME/Yandex.Disk.localized/Лунора/docs/"` | раз в неделю |
| копировать `research/`, память и транскрипт на Яндекс.Диск | раз в месяц |

## Чего не покрывают копии

| Что | Почему | Что делать |
|---|---|---|
| Ключ SSH к GitHub | лежит только на компьютере | завести токен в GitHub заранее |
| Ключ к серверу `mark_prod_ed25519` | то же | хранить копию в менеджере паролей |
| Опубликованные версии артефакта | живут в учётной записи Claude | не важно: источник — файл в git |
